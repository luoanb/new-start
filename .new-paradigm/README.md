# 使用教程

这套机制用于让人先确认需求和约束，再让 Agent 编写代码。本文件面向已经接入机制的项目使用者。

## 初始化

机制安装完成后，在项目根目录执行一次：

```bash
node .new-paradigm/init.js
```

它只下载指标检测工具自己的依赖，不修改项目的业务依赖。依赖没有变化时，重复执行是安全的。

## 1. 梳理需求

告诉 Agent：

> 帮我梳理这个需求：……

Agent 会起草需求文档，并询问会影响产品行为的关键问题。确认内容正确后，再明确批准需求。

## 2. 确认代码契约

告诉 Agent：

> 根据已确认的需求，起草或更新代码契约。

代码契约描述系统对外提供什么能力。检查无误后单独批准；批准需求不等于批准代码契约。

## 3. 确认实施计划

告诉 Agent：

> 根据需求和代码契约制定实施计划，先不要写代码。

确认修改范围、验证方式和停止点后，再明确批准计划。

## 4. 开始开发

告诉 Agent：

> 按已批准的计划开始执行。

Agent 会实现代码、运行项目检查和质量指标、核对代码契约，并汇报失败、例外和剩余风险。

## 5. 人工验收

根据需求文档中的验收条件检查实际结果。测试和指标通过只表示可以进入验收，不代表产品已经验收。

## 出现问题时

- 文档正确、代码错误：修复代码并重新检查。
- 需求、契约或规则错误：先修改并重新确认文档，再继续开发。
- 有关键问题尚未决定：停止开发，先完成决策。

Agent 的项目工作方式见 [AGENTS.md](../AGENTS.md)。
