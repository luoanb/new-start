# Pulsar 应用插件化迁移

> 文档状态：待确认
> 迭代编号：REQ-20261104-001
> 上位依据：《需求契约追溯规则》
> 适用范围：将 pulsar-app 的业务与界面迁移到 pulsar-host 插件体系，替代现有 Rust + SvelteKit + Tauri 单体实现
> 下位产物：代码契约、实现与验收结果

## 一、背景与目标

当前仓库并存两套体系：

- `packages/pulsar-app`：Rust 核心 + SvelteKit 前端 + Tauri 入口。Rust 源文件 121 个、约 4.85 万行，`#[tauri::command]` 标注 116 处（既有文档记为 108 个），前端文件 96 个。能力完整，但业务、界面与入口耦合在一个单体里，无法按能力装卸。
- `packages/pulsar-host`：TypeScript/Node 插件宿主。已具备 profile/bundle/patch 装配、Cordis fiber 生命周期、执行环境适配器（dom/solid）编译与投递、Slots、RPC、SSE、产物目录与 import map。

本次变化要解决的问题：让 Pulsar 从单体应用变成"一个宿主 + 一组可装卸业务插件"，复用 pulsar-host 已落地的机制，避免继续在双技术栈上叠加成本。

目标结果：

- 运行时收敛为一个 TypeScript/Node 宿主，业务与界面都以插件形式装载。
- 业务逻辑全部用 TypeScript 重写，Rust 实现降级为行为参考与对拍基准。
- 界面全部用 Solid 重写，通过 Slots 组合，视觉与交互与现版本等价。
- 用户既有数据（会话、课题、神经元、裁决、配置、工作区）可直接沿用。
- 行为契约以 `docs/pulsar/` 为权威来源；迁移前先完成文档与 Rust 实现的反向同步。

已确认决策：业务全量 TS 重写；UI 用 Solid 重写；pulsar-host 作为基建；Tauri 保留为窗口载体；业务数据沿用现有格式；桌面专属能力由宿主机制提供。

## 二、范围与非目标

范围：

- 宿主机制补齐（迁移前置）：插件 npm 依赖安装与解析、双向 WebSocket 通道、远程鉴权、浏览器端单实例消费 `@pulsar/plugin-client`、桌面载体启动与退出级联、桌面能力（窗口控制、文件对话框、打开链接、提权）、纯页面插件装配（`module` 可选）、页面依赖声明与运行期启停通知、事件序号与重连重拉协议、结构化 RPC 错误。
- 业务插件迁移：轮次内核与 hook 协议、Provider、工具（含 MCP）、文件/git/搜索、终端、会话存储、课题、神经元、助手与轮询、观测与日志、业务配置。
- 界面迁移：工作台（布局、标签页、分栏、视图容器、主题、国际化、快捷键）与各业务面板。
- 契约迁移：现有命令面改为插件命名空间 RPC；状态事件改为插件事件；前端数据获取不再依赖 Tauri invoke。
- 数据兼容：`.pulsar` 下的会话 JSON、`app.db` 表结构、工作区与配置文件保持可读可用。
- 交付批次（按域推进，非时间承诺）：
  1. 批次 0：宿主机制补齐与单实例契约包接入。
  2. 批次 1：轮次内核 + hook 协议 + Provider。
  3. 批次 2：工具 + 文件/git/搜索 + 终端。
  4. 批次 3：会话/课题/神经元/助手与轮询。
  5. 批次 4：工作台与面板 UI。
  6. 批次 5：数据兼容、入口壳、端到端验收与文档回写。

非目标：

- 不新增业务能力；本次只做行为等价迁移。
- 不保留 Rust 业务实现作为运行路径；Rust 代码仅用于参考与对拍。
- 不做插件市场、远程插件安装与版本分发。
- 不做 Vue/React 适配器，不做 RPC 类型自动生成。
- 不重做视觉设计；除框架差异导致的最小调整外，界面保持一致。
- 不做多租户、云同步、移动端。
- CLI、TUI 本期不迁移，后置处理；Tauri 仅作为桌面窗口载体保留。

## 三、用户场景与行为

- 桌面用户启动应用：Tauri 窗口拉起本地宿主，宿主按 profile 装配插件，界面由插件贡献渲染；启动完成后功能与现版本一致。
- 会话使用：新建/切换会话、发送消息、流式输出、工具调用与结果展示、中断生成、多会话并行；行为与现版本一致。
- 后台推进：轮询推进未完成课题、助手裁决与复盘、神经元选型；界面按事件增量刷新并最终收敛为全量数据。
- 工作区操作：文件浏览与编辑、搜索、git 操作与确认、终端会话、日志查看；护栏、确认流程与权限约束与现版本一致。
- 插件启停：禁用某业务插件后，其路由、RPC、插槽、定时任务与事件订阅全部消失且无残留；重新启用后界面不出现重复内容，命中已有产物不重新编译。
- 版本升级：用户带着既有 `.pulsar` 数据升级，会话、课题、神经元、裁决与配置无需手工迁移即可继续使用。
- 远程访问：浏览器访问需通过鉴权；未携带有效凭证的请求被拒绝，终端双向通道可用。
- 异常：单个插件加载失败只影响自身，其余插件与界面照常工作，错误在页面上可定位。

## 四、约束与假设

已确认决策：

- 业务全部用 TypeScript 重写，最终不保留 Rust 运行进程。
- 界面全部用 Solid 重写，不再使用 Svelte 组件。
- pulsar-host 与 pulsar-plugin-client 作为机制层，不承载任何业务。

边界判定口径（本次核对的统一标准）：

- 去掉 Pulsar 业务名词后仍成立的能力归宿主；含会话、轮次、神经元、课题、工具、Provider、git、终端等业务名词的归插件。
- 组合方式由 Cordis 服务依赖表达，现有 Gateway 组合根不再保留。
- 宿主只提供传输与机制：RPC 注册与调用、事件总线、插槽注册与渲染、产物编译与投递、启停回滚；业务语义、事件类型、鉴权策略、配置字段、数据布局归插件。
- 宿主只拥有编译产物目录；业务数据目录与格式归 app 插件，二者边界需在契约中写清。
- 入口层（桌面窗口、浏览器、CLI、TUI）只做适配，不实现业务分支。
- 插件之间不得互相 import，只允许通过服务依赖、事件、插槽、RPC 与 profile 覆盖连接。

服务与页面的关系（已确认）：

- 服务是业务状态的唯一权威，页面只做投影与交互；宿主只负责传输与装载，不理解两侧语义。
- 默认同域同插件：一个插件同时提供宿主服务与页面；纯服务插件与纯页面插件允许存在，纯页面插件不得携带业务逻辑。
- 页面取数遵循"先订阅、再快照、后合并"：默认按 `changed` 事件幂等重拉快照；只有聊天流式与终端输出使用带 `seq` 与 `done` 的增量；断线重连后重新拉取快照。
- 写操作用例归属本域：页面只调用拥有该用例的域 RPC，跨域编排在服务层完成，不在页面层拼装。
- 页面在 profile 声明 `requires`；宿主只在依赖启用时下发页面，运行期依赖被禁用时通知页面卸载或显示不可用。
- 工作台是唯一的布局拥有者；业务面板只注册到已声明的槽位，不得自造槽名。

文档与实现约束：

- `docs/pulsar/` 是行为契约的权威来源；与 Rust 实现不一致时先修文档，再按文档重写。
- 文档记载的命令数（108）与代码标注（116）不一致，属于迁移前必须核对的反向同步项。
- 迁移验收以文档契约与对拍记录为准，不以 Rust 代码的现状为准。

技术与兼容约束：

- 单运行时、单 UI 框架、单构建链；宿主不引入业务依赖。
- 原生能力直接依赖 Node 原生模块（node-pty、better-sqlite3、tree-sitter），git 走子进程；需明确跨平台打包与签名方案。
- 宿主必须支持插件 npm 依赖的安装与解析，否则业务插件无法落地。
- 页面只允许一张 import map，`@pulsar/plugin-client` 在页面内必须单实例。
- 性能不低于现版本：流式首字节延迟、PTY 吞吐、长会话与大批量工具结果的处理不得明显退化。
- 数据格式保持兼容：会话 JSON 字段、`app.db` 现有表结构、工作区与配置文件不得破坏性变更；不执行一次性格式迁移。

已确认的工程约束：

- Tauri 保留为桌面窗口载体，本地以 Node sidecar 方式启动宿主；CLI/TUI 后置。
- 本期范围为桌面 GUI 与浏览器远程访问，两者共用同一套插件与界面。
- 业务插件按域拆分，规模约 12 个。
- RPC 类型由各插件自带，另维护一份中心契约清单。
- 桌面专属能力（窗口控制、文件对话框、打开链接、提权）由宿主以机制方式提供，业务插件按需注入。

假设：

- 用户接受一次性重写带来的过渡期，且过渡期以新旧并行的对拍结果作为准入依据。
- Node 原生模块可在目标桌面平台完成打包与签名。

## 五、验收条件

- 宿主启动并完成 profile 装配后，全部业务域可用，运行时不依赖 Rust 进程；前端不直接依赖 Tauri command，桌面能力通过宿主机制获取。
- 桌面壳启动即拉起本地宿主（sidecar），退出时级联关闭；宿主启动失败时窗口可见可定位的错误。
- 核心链路等价：相同输入下，消息序列、工具调用序列、状态事件序列与 Rust 参考记录一致（以 golden fixtures 对拍）。
- 三种会话模式、hook 裁决、上下文压缩、后台轮询、神经元选型的行为与现版本一致。
- 工作台与全部业务面板功能等价：列表、交互、快捷键、国际化、主题与现版本一致。
- 启停闭环：任一业务插件禁用后，其路由、RPC、插槽、定时器与事件订阅全部消失，编译产物保留；重新启用命中已有产物且界面不重复。
- 页面与服务的关系：任一页面的写操作只调用本域 RPC，跨域编排不出现在页面代码中。
- 取数协议：页面先订阅后拉快照；`changed` 重拉幂等；流式增量跳号或断线后能通过快照恢复，不丢消息、不重复。
- 依赖与启停：禁用页面依赖的服务后，页面卸载或显示不可用，不出现静默失败；重新启用后恢复。
- 纯页面插件（工作台）可在没有宿主业务模块的情况下完成装配与渲染。
- 数据可用：现有 `.pulsar` 数据可直接打开（不执行格式迁移），会话、消息、课题、神经元、裁决、工作区与配置无丢失。
- 桌面能力（窗口控制、文件对话框、打开链接、提权）由宿主机制提供，业务插件只注入宿主服务。
- 中心契约清单覆盖约 12 个业务插件，逐项列出服务、RPC、事件与存储契约。
- CLI、TUI 不作为本期验收项。
- 契约完整：现有 116 处 command 标注（文档记 108）逐项有对应 RPC 或明确的废弃记录；前端不再直接调用 `invoke`。
- 远程模式：未授权请求返回 401；授权后 RPC、SSE 与终端 WebSocket 均可用。
- 质量门禁：宿主与各插件 `typecheck` 通过；`verify` 覆盖各插件启停与核心链路；至少一条端到端验收通过。
- 一致性：页面仅有一张 import map，无 `@pulsar/plugin-client` 多实例；README 与插件开发攻略与实现一致。
- 开发体验：修改单个插件的宿主面或 Client 面可热替换，不影响其他插件。

## 六、风险与待决策项

风险：

- 行为回归面大：轮次管线、hook 顺序、工具授权、压缩、轮询与神经元互相耦合，任何一处偏差都会影响主链路。
- 数据兼容失败会导致升级丢数据，属于最高优先级风险。
- Node 原生依赖（PTY/SQLite/语法解析）在桌面打包与跨平台 ABI 上存在不确定性。
- Tauri sidecar、原生模块与代码签名叠加，发布链路复杂度上升。
- 流式输出与终端吞吐在 Node 下需重新验证，可能出现性能退化。
- 双轨期口径漂移：已冻结 Rust 新功能（q7），但缺陷修复仍可能只落一侧；需以文档契约作为唯一基准。
- 文档滞后：命令数量等契约已出现文档与代码不一致，若不先反向同步会复制错误。
- 宿主机制缺口（依赖安装、WS、鉴权、单实例契约包）若后置，会导致中途返工。
