# 应用平台化：产品现状证据

> 采集时间：2026-11-12
> 用途：支撑探索中的事实断言；本文件不参与裁决。

## 1. `pulsar-app` 是历史废案

- 用户明确：`pulsar-app` 是原始阶段的废案，仅有产品设计参考作用（见 `需求原文.md`）。
- `packages/pulsar-app/src-tauri/tauri.conf.json` 只声明一个主窗口；窗口 `create: false`，由应用启动流程创建。
- `packages/pulsar-app/src/lib/layout/views.ts` 在编译期直接导入各业务组件，并以静态 `viewRegistry`、`mainViews` 注册。
- 上述代码只能说明废案曾采用固定单窗口工作台，不能作为当前产品基线、迁移对象或平台边界。

## 2. 当前可复用的平台机制位于动态插件宿主

- `packages/pulsar-host/src/profile.ts` 从 `profile.yml` 和 bundle 补丁合成扁平插件条目，支持覆盖与禁用。
- `packages/pulsar-host/src/types.ts` 的一个插件条目可包含 Host 入口与一个 Client 入口；浏览器通过 `BootGraph` 获取动态 Client 插件。
- `docs/pulsar-host/plugin-guide.md` 明确当前没有 npm 仓库安装和桌面壳；“安装”是放入源码、修改 profile、重启宿主。
- `pulsar-host` 尚未形成面向用户的桌面产品；不得以接入或改造 `pulsar-app` 作为默认前提。

## 3. 已有能力的粒度是插件，不是应用

- Host 插件已有依赖注入、生命周期回滚、RPC、事件和运行时启停。
- Client 插件已有 Slot、DOM/Solid 执行环境适配器、编译产物缓存和开发期热替换。
- 当前没有应用级 id、版本、图标、多个贡献的聚合清单、依赖关系、数据目录、安装来源、签名或更新语义。
- 当前禁用/卸载针对运行时插件条目，不等于从用户设备移除一个应用及其数据。

## 4. 安全与统一管理尚未形成

- `docs/pulsar-host/plugin-guide.md` 明确插件与宿主同进程、拥有宿主权限，只适合可信插件。
- Host 的 RPC/SSE 尚未形成愿景中的“一个门卫、一本账”；`pulsar-app` 废案里的工具授权与 Hook 裁决仅可作为产品设计参考。
- AI 创建插件并安装、人与 AI 使用同一套应用管理接口，当前都没有产品闭环。

## 5. 与“插座边界”探索的关系

- `../../EXP-20261111-001-插座边界/探索.md` 正在探索服务、页面、Skill、工具等贡献如何进入统一的插座树。
- 本探索把“应用”视为这些贡献的可安装聚合单元，关注用户看到的桌面、应用身份、安装与运行边界。
- 插座类型、共享状态归宿和门卫调用路径仍属于上游未决问题；本探索不得把其中任一候选当作已确认事实。

## 6. 从事实推出的待验证判断

- [推断] 平台化需要从桌面与应用模型重新立题，不能把 `pulsar-app` 的固定工作台结构默认继承为平台外壳。
- [推断] 仅把 profile 中若干插件打包在一起，仍不足以构成用户可理解、可审计、可迁移的应用。
- [推断] 桌面、应用内容与权限管理需要共享同一套身份和管理语义，否则人与 AI 无法真正同权操作。
