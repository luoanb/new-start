# 下一轮候选输入

> 采集时间：2026-11-12
> 用途：准备下一轮平台形态比较；本文件不包含候选、建议或人的决策。

## 已确认约束

- 应用是可安装的聚合单元，不等同于单个页面或插件。
- 桌面采用 OS 式语义，不承载具体业务。
- 人创建、AI 创建与外部安装都在探索范围内。
- 本轮不以最小闭环裁剪完整问题空间。

## 候选必须同时回答的维度

1. **应用身份**：聚合单元如何跨版本、来源和设备保持同一身份。
2. **内容归属**：页面、服务、Skill、工具是随应用携带，还是由应用引用独立贡献。
3. **运行边界**：窗口、后台活动、进程与崩溃隔离分别归桌面还是应用管理。
4. **数据延续**：更新、卸载、重装和迁移分别保留什么。
5. **权限与账本**：安装、启动、调用能力和数据访问如何经过同一门卫。
6. **来源与信任**：内建、人写、AI 写、社区分发的差异是否只影响审查与授权。
7. **增长方式**：应用如何创建、安装、更新、停用、移除，并让桌面实时感知。

## 比较时需要补足的证据

- 用户对“关闭窗口、退出应用、保留后台任务”的预期。
- 用户对卸载后保留数据、授权记录和应用身份的预期。
- “插座边界”探索对共享状态归宿与门卫调用路径的决定。
- 现有 Tauri 多窗口、子进程隔离与动态前端贡献能否承载候选形态的只读验证。

## 下一步

用户修正 `探索.md` 的问题边界后，基于以上同一组维度提出至多三个互斥候选；每个候选必须写最强反对和六个月失败预演。
