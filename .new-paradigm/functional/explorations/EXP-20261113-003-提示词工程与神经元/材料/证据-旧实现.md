# 旧 App 提示词与神经元证据

> 采集时间：2026-11-13
> 用途：为探索提供可定位的历史输入；本文件不参与裁决。
> 范围：已废弃的 `packages/pulsar-app` 及其 `docs/pulsar/` 文档。

## 1. 旧概念的稳定部分

`docs/pulsar/neuron/index.md` 将神经元描述为“可被选中并当系统/知识文本执行的能力节点”，其核心数据包括短标签、可执行内容、权重、工具权限与网络位置。

`docs/pulsar/neuron/data-model.md` 说明节点创建时权重恒为零，权重只经后续评价增减；因此权重表达后验价值，而非创建者预设的重要性。

`docs/pulsar/neuron/services.md` 将对外能力收敛为提示词选择与评价反馈，调用方无需理解候选池、模型选型和权重回退等内部细节。

## 2. 提示词工程与神经元的关系

`docs/pulsar/assistant-prompt-synthesis.md` 将提示词分成三层：

- 神经元承载“是谁、怎么做”的角色与能力文本，通常进入 system 位置。
- Insert 承载“本轮要做什么、输出什么格式”的操作说明书。
- `ModelCallInput` 负责把历史、角色、说明书和本轮输入装配成模型调用。

这说明神经元是提示词资产的一种运行时载体，不等于完整的提示词工程。

## 3. 值得继续验证的机制

- 角色能力与操作说明书分离，避免输出契约污染长期角色内容。
- 创建权重为零，经评价形成价值，再影响后续选型。
- 内容版本链与人工编辑锁，为“能看、能改、自动演化不覆盖人工决定”提供基础；版本链不因此成为产品回退能力。

来源：`docs/pulsar/assistant-prompt-synthesis.md`、`docs/pulsar/neuron/data-model.md`、`docs/pulsar/neuron/lifecycle.md`。

## 4. 不应默认继承的旧债务

- `system_type` 同时承载创作者、选型器、裁决指令和会话规范，且被多模块硬编码；`docs/pulsar/neuron/roadmap.md` 已标记其语义不清。
- 默认容量 300、定时删除低价值节点，与愿景中的“越攒越多”存在张力。
- Insert 编译进旧 App 二进制，神经元机制又与 Tauri、SQLite 和旧 Gateway 装配耦合，不符合新平台的可替换方向。
- 自动演化主要作用于创建器变体，不能等同于全部提示词都会自我学习。

## 5. 新平台现状

`packages/pulsar-kernel/README.md` 明确不承接旧 `system-prompt` 等 core 能力；在 `packages/pulsar-host` 与 `packages/pulsar-kernel` 中也没有可直接复用的神经元域。新平台需要先决定产品概念和插件边界，不能把旧实现视为迁移方案。
