## 2. 神经元的定义与五条链路

`docs/pulsar/neuron/index.md`：

> 神经元是"一个可被选中并当系统/知识文本执行的能力节点"。
> 神经元 = 能力节点：`desc`（≤20 字标签）+ `content`（可执行提示词/知识块）+ `weight` + `tool_ids` + 网络位置。

`docs/pulsar/neuron/services.md`：对外两个服务——提示词服务（`select_role`，返回选中节点的 content + 工具授权）与评价服务（`apply_score_feedback`，把分数落成节点权重、边 delta、lineage 归因并触发演化）。

`docs/pulsar/neuron/lifecycle.md`：创建（pool→7→1 → 模型返回 JSON 列表 → 落库）→ 选型（n=1 短路 / LLM / 权重回退）→ 打分 → creator 变体演化（observing→active / 回滚 / 差分重写）→ 容量回收（超 `neuron.capacity` 默认 300 删低价值，系统神经元豁免）。

## 3. system_type 的硬编码债

`docs/pulsar/neuron/roadmap.md` §2.2：

> 状态：语义不清，暂停优化。
> 以下 system_type 被多个独立模块硬编码引用，是编译期常量……删除任一系统节点，对应引用模块即失效。

## 4. 容量与回收

`docs/pulsar/neuron/data-model.md`、`lifecycle.md`：普通节点超 300 时按低价值逻辑删除；系统节点豁免；节点与边创建权重恒 0，只经评价增减。

## 5. 提示词合成现状

`docs/pulsar/assistant-prompt-synthesis.md` §1、§5、§6：

> 一轮统一为 beforehook → run_core → afterhook；全部模型调用的 messages 经 `ModelCallInput::assemble` 产生。
> 神经元 = 角色/能力载体（是谁、怎么做）→ 通常在 `role_system`；操作说明书 = 工具与输出契约 → 作为 `Manual` 的 `content`；角色人设不进 insert；输出格式契约不进 neuron 长文。
> 主对话：`role_system = 选中业务 neuron.content`，模板 `Neuron`；裁决类：`role_system = 系统 neuron.content` + insert 说明书，模板 `Manual`。
