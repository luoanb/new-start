# 产品术语表格式

本文件是 `requirement-authoring` Skill 的执行资料，不是独立权威规则。与生效治理规则冲突时，以治理规则为准。

路径固定为 `functional/product/术语表.md`。条目结构沿用机制术语表：定义、边界、废弃别名。按业务领域分章，章节内条目按名称排序。

```markdown
# <产品名>术语表

> 文档状态：<草案|待确认|生效|废弃>
> 上位依据：《需求契约追溯规则》及适用的生效产品方向文档
> 适用范围：本项目全部需求、契约和代码中的业务概念命名
> 下位产物：探索实例、需求实例、代码契约公共类型、实现代码中的业务命名

## 使用规则

沿用《术语表》第一节的使用规则。本文只定义业务概念，不收录机制概念。

## <业务领域一>

### <概念名>

**定义**：<这个概念在业务上是什么，一句话>

**边界**：<它不是什么；与易混淆概念的区别>

**废弃别名**：<曾用名或口语叫法，或“无”>

**英文命名**：<代码契约和实现中对应的英文标识，可选>
```

写作判据：

- 定义写业务含义，不写数据字段；字段形状属于代码契约。
- 只收录跨需求稳定的概念；单次需求的临时概念在需求文档内就地说明。
- 一个概念只有一个规范名称；需求或口语中的其他叫法进入废弃别名。
- 产品术语表可以基于已确认的产品语义独立新增或修改，不要求绑定需求实例。
- 术语由探索或需求讨论发现时，应记录语义来源；可以与需求同批评审，但必须先确认术语，再确认依赖它的需求。
- 文末保留“变更说明”章节，每次变更一行。
