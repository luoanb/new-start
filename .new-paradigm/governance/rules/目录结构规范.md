# 目录结构规范

> 文档状态：生效
> 上位依据：《落地策略》《术语表》《文档治理规则》
> 适用范围：项目根目录及 `.new-paradigm/` 项目上下文目录
> 下位产物：项目目录、治理资产和功能区文档的物理位置

## 一、目的

规定人机协同编程机制在项目中的物理边界和资产位置。本文件使用 `DIR` 作为目录结构领域的规则编号前缀。

## 二、规则

### DIR-001 项目目录结构

- **规则**：项目资产必须按以下目录结构存放。尚未产生实际资产的目录可以不创建，但资产一旦产生，必须进入对应位置。

```text
/
├─ .new-paradigm/              # 人机协同编程机制的项目上下文
│  ├─ README.md                # 面向人的使用教程
│  ├─ init.js                  # 使用者初始化指标工具依赖
│  ├─ AGENTS.md                # 机制完整 Agent 工作指引
│  ├─ installation.json        # 安装器生成的机制版本与受管文件状态
│  ├─ governance/              # 治理区：跨功能生效的规范与能力
│  │  ├─ principles/           # 供人阅读的原理、理念、术语和方法论
│  │  │  └─ originals/         # 未修改的原始理论输入
│  │  ├─ rules/                # 直接约束项目的治理规则
│  │  ├─ skills/               # 面向 AI 的可复用任务能力
│  │  │  ├─ requirement-authoring/ # 需求立约
│  │  │  └─ code-delivery/         # 代码交付
│  │  ├─ metrics/              # 指标定义与检测能力
│  │  │  ├─ definitions/       # 结构化的指标、口径和阈值
│  │  │  ├─ tools/             # 按语言组织的指标采集和检测工具
│  │  │  │  └─ javascript/     # JavaScript/TypeScript 及前端框架适配器
│  │  │  └─ overrides.json     # 可选的项目阈值与适用范围覆盖
│  │  ├─ templates/            # 需求、契约等通用模板
│  │  ├─ distribution/         # 可移植资产清单与版本边界
│  │  ├─ tools/                # 跨领域治理工具
│  │  │  ├─ project-lifecycle/ # 安装、状态检查、升级与卸载工具
│  │  │  └─ contract-overview/ # 从代码契约生成关系总览
│  │  └─ plans/                # 治理机制的建设计划
│  ├─ functional/              # 功能区：产品需求与当前有效契约
│  │  ├─ requirements/         # 按迭代保存用户功能变更诉求
│  │  │  └─ <迭代编号>-<名称>/
│  │  │     ├─ 需求.md
│  │  │     └─ 视觉设计.md     # 可选
│  │  └─ contracts/            # 当前有效代码契约及生成式总览
│  │     ├─ overview.md        # 生成，不参与裁决
│  │     └─ <domain>/
│  │        ├─ <capability-name>.md
│  │        └─ <name>-collaboration.md
│  └─ deprecated/              # 不参与当前裁决的已废弃历史规范
├─ src/                        # 功能实现代码
├─ tests/                      # 实现验证代码
├─ README.md                   # 机制仓库介绍与安装流程
└─ AGENTS.md                   # 项目原有指令与机制发现片段
```

- **理由**：稳定的物理位置使人和 AI 能够发现权威治理资产，并隔离当前依据、功能语义和废弃材料。
- **验证**：人工或 AI 对照目录树检查现有文件位置、重复副本和未定义目录。
- **例外**：特定技术栈要求的项目文件可以位于根目录或其惯用位置，但不得改变 `.new-paradigm/` 内治理资产和功能区文档的职责边界。

## 三、统一例外要求

新增顶级目录或改变既有目录职责属于实质性规则变更，必须先更新本文件并重新确认。
