# 指标治理规则

> 文档状态：生效
> 上位依据：《编程新范式》《落地策略》《术语表》《文档治理规则》《治理规则编写规则》《代码交付规则》
> 适用范围：`.new-paradigm/governance/metrics/` 下的指标定义、项目覆盖、语言适配器和检测结果
> 下位产物：结构化指标定义、项目覆盖文件、检测工具、检测结果和交付处置

## 一、目的

建立从质量风险、计算口径、默认阈值到检测结果和处置方式的稳定关系，使不同语言适配器读取同一份指标定义，并避免工具通过实现细节反向修改质量标准。本文件使用 `MET` 作为指标治理领域的规则编号前缀。

## 二、规则

### MET-001 指标定义结构

- **规则**：每项指标必须使用独立 JSON 文件定义，并包含 `schemaVersion`、`documentStatus`、`id`、`name`、`upperBasis`、`purpose`、`risk`、`applicability`、`measurement`、`defaultPolicy`、`overridePolicy` 和 `downstreamProducts`。指标标识必须采用 `QLT-NNN`，生效后禁止复用。
- **理由**：统一结构使人、AI 和不同语言工具能够共享同一质量口径。
- **验证**：使用 JSON Schema 和人工评审检查字段、类型、枚举和标识唯一性。
- **例外**：无。

### MET-002 计算口径

- **规则**：`measurement` 必须声明单位、方向、计算方法、数据要求和必要参数。计算方法必须达到不同适配器在相同输入下可得到等价语义结果的程度，禁止只记录指标名称或工具命令。
- **理由**：工具名称不是指标口径，同一工具也可以产生多种不同测量结果。
- **验证**：由另一实现者仅依据定义复述输入、计算和结果单位；无法唯一复述时视为未完成。
- **例外**：无。

### MET-003 语言与工具解耦

- **规则**：指标定义必须描述语言无关的质量特征，禁止写入某个采集工具的专用参数或输出路径。语言适配器必须通过映射清单声明指标与采集器关系，并记录采集工具和版本。
- **理由**：指标语义稳定后，可以增加语言或工具实现而不改写质量目标。
- **验证**：检查指标定义是否引用具体工具配置，以及适配器结果是否包含工具证据。
- **例外**：只对特定资产类型适用的指标可以声明适用条件，例如“存在静态类型检查器”或“包含前端源码或模板”。

### MET-004 默认阈值与阻断

- **规则**：每项生效指标必须声明比较运算符、默认阈值和结果等级。首批指标默认等级为 `block`；实际值不满足有效阈值时，结果必须为 `fail` 并阻止无说明交付。
- **理由**：度量值只有结合阈值和处置方式后才能形成指标约束。
- **验证**：使用低于、等于和高于边界的样例检查比较结果。
- **例外**：指标明确不适用于目标项目时按 MET-006 处理，不得通过放宽阈值伪装成不适用。

### MET-005 项目覆盖

- **规则**：项目可以通过 `.new-paradigm/governance/metrics/overrides.json` 调整指标阈值或适用范围，但每项覆盖必须包含指标标识、覆盖值、理由、批准人、适用范围和失效条件。覆盖禁止修改指标单位、计算方法、方向或结果状态语义。
- **理由**：不同项目风险不同，但项目差异不能改变指标本身的含义。
- **验证**：检查覆盖字段、批准依据、当前有效性和覆盖前后计算口径。
- **例外**：无。

### MET-006 结果状态

- **规则**：单项指标结果必须是：
  - `pass`：数据有效且满足有效阈值；
  - `fail`：数据有效但不满足有效阈值；
  - `not_applicable`：指标适用条件明确不成立，并提供理由；
  - `error`：配置、数据、依赖或检测执行失败，无法形成有效值。
  `error` 禁止被计为通过；缺少必需输入时禁止使用 `not_applicable` 掩盖错误。
- **理由**：不适用与无法检测具有不同风险，必须明确区分。
- **验证**：为四种状态提供 fixture，并检查状态、理由和证据。
- **例外**：无。

### MET-007 统一检测结果

- **规则**：检测结果必须包含运行标识、目标项目、适配器及版本、开始和结束时间，以及每项指标的标识、实际值、有效阈值、状态、证据、工具版本和错误信息。结果可以输出到 stdout 或用户指定文件，默认不得写入项目仓库。
- **理由**：完整证据使结果可以审查、复现和用于交付处置。
- **验证**：按结果结构检查必填字段，并从证据定位原始工具输出。
- **例外**：可能包含敏感信息的原始输出必须脱敏或仅保留安全摘要。

### MET-008 进程退出码

- **规则**：统一检测入口必须使用退出码 `0` 表示全部适用指标通过，`1` 表示至少一项指标失败且没有执行错误，`2` 表示存在配置或检测执行错误。存在 `error` 时必须优先返回 `2`。
- **理由**：稳定退出码使人、Skill 和 CI 能够一致处理结果。
- **验证**：使用全通过、指标失败、执行错误和失败与错误并存的 fixture 检查退出码。
- **例外**：无。

### MET-009 工具稳定性

- **规则**：语言适配器必须锁定直接和传递依赖版本，记录运行环境要求，并为第三方工具输出建立归一化层。工具升级必须验证结果结构和指标语义未发生未说明变化。
- **理由**：第三方工具升级可能改变默认规则、输出结构和测量结果。
- **验证**：检查锁文件、工具版本证据和升级回归测试。
- **例外**：安全修复可以优先升级，但在交付前仍必须完成受影响指标回归。

### MET-010 适配器完整性

- **规则**：适配器声称支持的语言、框架和文件类型必须具有对应解析器、采集器及通过与失败 fixture。无法确定框架、解析器或配置时必须返回 `error`，禁止静默跳过后报告通过。
- **理由**：文件被遍历不等于文件被正确解析，静默遗漏会产生虚假质量结论。
- **验证**：为每个支持矩阵放置明确违规样例，并确认违规进入对应指标证据。
- **例外**：用户明确排除的路径可以不检测，但排除范围必须出现在运行配置和结果证据中。

## 三、结构化字段约定

- `documentStatus` 使用 `draft`、`pending_confirmation`、`active` 或 `deprecated`。
- `measurement.direction` 使用 `min` 或 `max`。
- `defaultPolicy.severity` 首批固定为 `block`。
- `overridePolicy` 只允许声明阈值与适用范围是否可覆盖。
- 项目覆盖不属于指标定义，不得写回 `definitions/`。

## 四、统一例外要求

任何例外均不得把 `error` 改写为 `pass`，不得修改指标计算口径，也不得省略批准人、理由和失效条件。

## 五、变更说明

- 首版：建立指标定义结构、语言工具解耦、默认阈值、项目覆盖、结果状态、退出码和适配器完整性规则。
- 本次：QLT-001 的计算口径明确不重复计入已归入 QLT-007 或 QLT-011 的违规，使各项阈值覆盖只作用于对应指标。
