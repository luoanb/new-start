# 需求契约追溯规则

> 文档状态：生效
> 上位依据：《编程新范式》《落地策略》《术语表》《文档治理规则》《治理规则编写规则》《目录结构规范》
> 适用范围：需求实例、可选视觉设计文档及需求到代码契约的追溯关系
> 下位产物：需求实例、需求立约 Skill、代码契约及相关检查能力

## 一、目的

规定需求、可选视觉设计和代码契约之间的职责边界、确认门禁及单向追溯关系。本文件使用 `RCT` 作为需求契约追溯领域的规则编号前缀。

## 二、规则

### RCT-001 需求实例边界

- **规则**：一次可识别的功能变化必须使用一个独立需求文件夹，路径为 `functional/requirements/<迭代编号>-<名称>/`。迭代编号必须采用 `REQ-YYYYMMDD-NNN`，文件夹内必须包含 `需求.md`，可以包含 `视觉设计.md`。
- **理由**：以文件夹为需求实例边界，可以将必需需求语义与可选视觉说明组织在一起，同时避免不同需求互相混杂。
- **验证**：人工或 AI 检查目录、编号和必需文件是否符合约定。
- **例外**：无。

### RCT-002 需求文档职责

- **规则**：需求文档必须说明本次变化为什么做、做什么、明确不做什么以及何时算完成，禁止展开可自由替换的内部代码结构。
- **理由**：需求文档是产品意图和产品验收的权威来源，不应替代代码契约或实现设计。
- **验证**：人工判断目标、范围、行为和验收条件是否足以确认产品结果；AI 审查是否混入无必要的内部实现。
- **例外**：会直接影响产品约束或验收结果的技术限制必须写入需求文档，但不得据此预先指定全部内部实现。

### RCT-003 需求文档篇幅结构

- **规则**：需求文档正文禁止超过七个一级章节，元数据不计入章节数。具体章节名称、顺序和输出格式由需求立约 Skill 管理，不在本规则中固定。
- **理由**：限制顶层结构可以保持需求可审核，同时允许 Skill 根据实际复杂度组织内容。
- **验证**：AI 审查一级章节数量，并检查具体格式是否来自适用 Skill，而非被误认为独立权威规则。
- **例外**：无。

### RCT-004 视觉设计职责

- **规则**：视觉设计文档可以省略。存在时，只描述页面结构、交互状态和视觉约束；其中任何影响产品行为、业务约束或验收结果的内容，必须同步写回需求文档后才能参与立约。
- **理由**：视觉设计用于补充表现层信息，不能形成与需求文档并列的产品行为来源。
- **验证**：人工或 AI 对照两份文档，检查行为和验收语义是否只在视觉设计中出现。
- **例外**：纯视觉属性不要求复制到需求文档。

### RCT-005 待决策项门禁

- **规则**：会改变目标、范围、行为、验收条件或重要契约方向的待决策项未解决时，禁止将相关需求视为已完成立约，也禁止进入对应代码契约确认或实现。
- **理由**：关键语义未确定时继续向下，会迫使 AI 用推断替代用户决定。
- **验证**：人工确认待决策项是否均已得到明确决定；AI 审查未决项是否会改变后续语义。
- **例外**：与当前交付范围无关且已明确延期处理的事项，可以移出本次需求并记录后继续。

### RCT-006 分离确认

- **规则**：需求文档和代码契约必须分别获得用户确认。需求获批只表示产品意图生效，不自动使相关代码契约生效。
- **理由**：需求确认“做什么”，代码契约确认“实现对外呈现什么”，二者承担不同责任。
- **验证**：检查两类文档各自的文档状态及确认依据。
- **例外**：无。

### RCT-007 单向契约追溯

- **规则**：需求文档必须列出本次受影响的全部能力契约和协作契约。已存在的契约使用可定位的相对路径；尚未创建的契约使用明确计划标识，并在契约创建后替换为实际路径。代码契约禁止反向维护关联需求列表，生成式契约总览不属于需求追溯目标。
- **理由**：需求侧需要同时明确单个能力和跨能力关系的影响范围；契约侧保持当前语义简洁，变更来源可以通过需求引用和 Git 历史查询。
- **验证**：从需求文档检查全部受影响能力契约和协作契约是否可定位；检查契约正文是否包含反向需求清单；检查需求是否误将生成式总览列为权威契约。
- **例外**：确认不影响任何代码契约的纯视觉变化，可以明确记录“无影响契约”及理由。

### RCT-008 权威来源

- **规则**：具体需求格式和起草步骤必须由适用的需求立约 Skill 提供，但 Skill 禁止新增本规则未定义的强制约束。需求与 Skill 冲突时，必须以本规则及已生效需求文档为准。
- **理由**：规则定义约束，Skill 定义做法，二者必须保持单向依赖。
- **验证**：检查 Skill 是否引用本规则，是否把格式建议包装成额外治理规则。
- **例外**：Skill 可以在七章限制内根据任务特点合并、拆分或省略非必要内容。

## 三、统一例外要求

本规则中的例外只适用于对应条目。任何例外均不得绕过用户确认、待决策项门禁或需求对受影响契约的追溯责任。
