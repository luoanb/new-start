# Micro Spec：模型文案改名 + 编辑面板支持设置默认模型

- 日期：2026-08-23
- 状态：已批准并执行

## 背景

1. 面板/视图文案「模型管理」过长，统一改为「模型」。
2. 后端已完整支持 `config.json` 顶层 `defaults`（provider + model）的读取、写回与校验
   （`get_config_view` / `write_config` / `validate_provider_config`），但前端编辑面板
   （ProviderManager）只读展示 `defaultsHint`，无设置入口。

## 变更

### 1. i18n 文案（translations.ts）

「模型管理」→「模型」（zh）；「Model Manager」→「Models」（en）：
- `sidePanel.models`（左侧面板标题）
- `views.providersModels`（视图注册标题）
- `views.providerManager`
- `providerManager.modalTitle`（编辑面板标题）

新增 key（zh/en + 类型）：
- `providerManager.defaultModel` = 默认模型 / Default model
- `providerManager.defaultProvider` = 默认服务商 / Default provider
- `providerManager.defaultClear` = 清除默认 / Clear default

移除不再使用的 `providerManager.defaultsHint`（旧只读提示，已被编辑区取代）。

### 2. ProviderManager.svelte：默认模型设置区

- 全局区（不依赖左侧选中项），位于 loading 判断之后、manager-body 之前。
- 两个下拉：默认服务商（options = 启用的 providers）+ 默认模型（options = 所选 provider 的 models）。
- 交互：
  - 选择服务商后自动带上该服务商第一个模型（或保留原模型若仍存在）；无模型则置空 defaults。
  - 选择模型写入 `view.defaults`；清空模型 = 清除 defaults。
  - 「清除默认」按钮置 `view.defaults = null`。
- 保存链路不变：`saveConfig` → `save_provider_config` → 后端校验引用存在后写回 + 热重载。
- footer 移除只读 `defaultsHint` 行，按钮右对齐。
