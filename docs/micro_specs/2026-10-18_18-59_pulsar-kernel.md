# Spec: pulsar-kernel（Cordis 框架层新建项目）

## Goal

- 要解决什么问题：在 `packages/` 下新建 `pulsar-kernel`，只承载 DeepSeek Harness 的“标准一”字面核心——Cordis 框架层（9 个 vendored 包，约 6,500 行），不含任何 harness 业务插件。
- 验收结果：项目可独立安装依赖、通过类型检查、用最小入口启动一个 Cordis 插件树并正常退出。

## Done Contract

- 什么算完成：`packages/pulsar-kernel` 目录结构、9 个 vendored 包、最小 TS 启动入口与说明文档齐备。
- 由什么证明：`pnpm install` 成功；`pnpm typecheck` 通过；`pnpm start` 输出启动与销毁日志；目录内无 harness 业务包（core/session/tools/agent/llm 等）。
- 哪些情况仍算未完成：无法解析 `@deepseek-ai/*` 包、类型检查报错、启动入口无法运行、或混入任何业务插件代码。

## Scope

- In：
  - 复制 `deepseek-harness/vendor/` 下 9 个包：`cordis`、`cosmokit`、`schemastery`、`loader`、`include`、`group`、`timer`、`hmr`、`logger-console`。
  - 新建独立 pnpm workspace、`tsconfig`（paths 指向 vendor 源码）、`.gitignore`、`README.md`。
  - 最小可运行入口：`src/kernel.ts`（类封装）+ `src/index.ts`（直接运行示例）。
- Out：
  - core 六包（session/system-prompt/tools/agent/agent-loop/scope）、llm、session、storage、settings 等一切业务或基础设施插件。
  - Web/桌面 UI、Tauri、构建发布流水线、测试框架、CI。
  - 对 vendor 源码的任何修改（保持与 DeepSeek Harness 完全一致，含其本地补丁）。

## Facts / Constraints

- 已确认事实：
  - vendor 9 包合计 6,474 行 TS（含 DeepSeek 的 24 项本地修改），作用域为 `@deepseek-ai/*`。
  - 外部运行依赖：`@standard-schema/spec`、`js-yaml`、`chokidar`、`picomatch`、`@babel/code-frame`、`supports-color`、`node-addon-require-builtin`。
  - 本机 Node `v24.22.0`、pnpm `11.5.1`，满足 `engines` 要求。
- 技术/业务约束：
  - vendor 包 `main` / `exports` 指向 `lib/index.js`，该文件由 DeepSeek 的 tsdown 构建产生；本项目不引入 tsdown，因此通过 tsconfig `paths` + `tsx` 直接消费 vendor 源码。
  - 仓库约定：接口先行、可复用逻辑优先用类（`.cursor/rules/law/ts-style.mdc`）。
  - 不修改 vendor 源码，避免产生第 25 项本地修改记录。
- 已知风险：
  - `tsx` 对 tsconfig `paths` 的解析行为需实测；若失败，退化为在 `src` 内用相对路径直接引用 vendor 源码（仍不修改 vendor）。
  - pnpm 首次安装需要网络拉取外部依赖。

## Restated Understanding

- 我理解当前任务是：把 DeepSeek Harness 中“去掉所有插件后剩下的字面核心”——Cordis 框架层——单独抽成一个新项目 `pulsar-kernel`。
- 当前核心目标是：得到一个约 6,500 行、可独立运行、无任何 harness 业务代码的框架工程。
- 当前边界是：只搬 vendor 9 包 + 最小启动入口；不搬 core 六包与任何能力插件。
- 暂不处理：构建产物发布、测试体系、UI 外壳、后续业务插件设计。

## 接口契约设计

```ts
// src/kernel.ts
export interface KernelOptions {
  /** 是否挂载 console 日志导出器，默认 true */
  logger?: boolean
}

/** 最小 Cordis 运行时：创建根 Context、挂载框架插件、可逆销毁。 */
export class KernelRuntime {
  readonly root: Context

  constructor(options?: KernelOptions)

  /** 启动运行时并输出就绪日志；重复调用幂等。 */
  start(): Promise<void>

  /** 销毁插件树，释放全部 effect / 监听器。 */
  stop(): Promise<void>
}
```

```ts
// src/index.ts
export { KernelRuntime } from './kernel.ts'
export type { KernelOptions } from './kernel.ts'

// 作为入口直接运行时：start -> 等待 1 个 tick -> stop
```

演示插件（`src/kernel.ts` 内部）：注册一个 `demo` 服务 + 一个 `kernel/ready` 事件监听，打印服务调用结果，卸载时打印销毁日志，用于证明生命周期与可逆注册。
