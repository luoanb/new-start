# Spec: 会话上下文压缩 (Compaction)

## Goal

- 要解决什么问题：
  长期对话累积的消息量超过模型上下文窗口限制时，模型报 `context length exceeded` 或丢失早期关键信息。需要将早期对话用 LLM 浓缩为一段摘要，替换到上下文链中，释放 Token 空间给后续轮次。

- 验收结果：
  长期对话（50+ 轮）不会因上下文超限而中断；每次模型调用前自动检查 Token 估算值，必要时执行压缩并保留最近 N 轮完整消息；原始会话文件不受影响。

## Done Contract

- 什么算完成：
  `Gateway::send_model_message` 中集成预检 → 压缩 → 发送链路；压缩摘要以 `Compaction` 类型存入会话；提供配置开关与参数；TUI 显示压缩进度 TaskBlock。
- 由什么证明：
  单元测试覆盖压缩触发条件与摘要插入；手动模拟 30+ 轮对话确认上下文不超限且摘要可见。
- 哪些情况仍算未完成：
  压缩后模型回复质量严重下降、压缩过程阻塞用户太久无反馈、或 Token 估算与实际偏差过大导致压缩无效。

## Scope

- In:
  - 简单 Token 估算（chars/4），依赖模型 `context_window` 字段
  - 自动压缩：每次 `send_model_message` 前检查阈值，超标则触发
  - 手动压缩：`/compact` 命令手动触发
  - 压缩边界：旧消息→LLM 摘要，最近 N 轮保留完整
  - 摘要以 `MessageRole::Compaction` 条目存入会话
  - 压缩使用与对话相同的模型调用
  - 压缩前后原始消息不删除
  - 可配置参数：`compaction.enabled`, `compaction.threshold_ratio`, `compaction.keep_last`

- Out:
  - 记忆刷写（Memory Flush → memory/ 目录落地）
  - 多级 DAG 摘要树
  - Streaming 压缩进度反馈
  - 使用独立廉价模型做压缩
  - 磁盘文件级压缩（zstd）

## 架构调整

当前问题：Gateway 既做路由又做业务编排。`send_model_message` 内部直接操作 Storage、拼接上下文、调 ProviderRegistry。Engine 不存在，AgentRuntime 名不副实。

调整为：

```
┌──────────────────────────────────────────────┐
│                 Gateway                       │
│  (总出口 — 所有外部调用只跟它打交道)            │
│                                               │
│  send_model_message() {                       │
│    self.engine.chat(input, options)           │
│  }                                            │
│  send_message() { ... }                       │
│  list_*() / status() / ...                    │
├──────────────────────────────────────────────┤
│  内部持有：                                     │
│  ├─ Engine             ← 编排层（新建）         │
│  ├─ ConversationStore  ← 会话存储（原名Storage）│
│  ├─ ProviderRegistry   ← 模型路由（不变）       │
│  └─ SkillRegistry      ← 技能（不变）           │
└──────────────────────────────────────────────┘
```

Engine 内部：

```
Engine {
    store: ConversationStore,    // 读写会话
    providers: ProviderRegistry, // 调模型
    compactor: Compactor,        // Token估算 + 压缩
}

chat(input, options) {
  1. store.get(conversation_id)         → 取会话
  2. compactor.ensure_fits(conv, model) → 压缩（自动判断）
  3. providers.call_model(request)      → 调模型
  4. store.add_message(msg)             → 存结果
}
```

| 模块 | 职责 | 变化 |

### Engine 接口

```rust
pub struct Engine {
    store: ConversationStore,
    providers: ProviderRegistry,
    compactor: Compactor,
}

impl Engine {
    pub async fn chat(
        &mut self,
        input: &str,
        options: ChatOptions,
    ) -> AppResult<ChatResponse>;
}
```

`chat` 调用流程：

```
1. resolve conversation_id
2. store.get(conversation_id) → conversation
3. compactor.ensure_fits(&mut conversation, &providers, context_window) → 可能压缩
4. 构建上下文（compaction 摘要 + 最近消息）
5. providers.call_model(request) → 调模型
6. store.add_message() → 存用户消息 + 响应
7. return ChatResponse
```

### Compactor 接口

```rust
pub struct Compactor {
    config: CompactionConfig,
}

pub struct CompactionConfig {
    pub enabled: bool,
    pub threshold_ratio: f64,  // 0.0~1.0, 默认 0.7
    pub keep_last: usize,      // 保留最近 N 轮, 默认 10
}

impl Compactor {
    /// 若会话超出阈值则执行压缩，返回是否实际执行了压缩
    pub async fn ensure_fits(
        &self,
        conversation: &mut Conversation,
        providers: &ProviderRegistry,
        model: &ChatModelSelection,
    ) -> AppResult<bool>;
}
```

`ensure_fits` 内部：

```
1. estimate_tokens(conversation) → usize
2. if tokens < context_window * threshold_ratio → return Ok(false)
3. 确定压缩边界：messages[..cutoff] 为旧消息，messages[cutoff..] 为最近 keep_last 轮
4. 组装压缩提示词
5. providers.call_model() → 得到摘要
6. 用 summary 构造 Compaction 消息
7. 插入 conversation.messages（在 cutoff 位置）
8. return Ok(true)
```

### 调用流程变化

`send_model_message` 内部改为委托 Engine：

```
Gateway::send_model_message(input, options)
  → self.engine.chat(input, options)
      → store.get()
      → compactor.ensure_fits()
          → estimate_tokens()
          → if > threshold: call_llm() → insert_summary() → save
      → providers.call_model()
      → store.add_message()
      → return response
```
