## Facts（代码事实）

- `Tool` trait：`name() / description() / parameters() / async execute(args) -> AppResult<String>`（`core/tool_registry.rs`）。
- `ToolRegistry::register` 强制 `InsertCatalog::require(name)`，`inserts/<name>.md` 缺失则 panic。
- 生产组装 `gateway.rs:84` 使用空注册表 `ToolRegistry::new()`，注释明确"外部工具待自描述 insert 后上架"。
- `engine.agent_mode` 循环：模型返回 `tool_calls` → `registry.execute` → 结果以 `msg_type: "tool_result"` 的 Assistant 消息落库（`engine.rs:260-269`）。
- 前端 `Message.msg_type` 字段已存在，但 `ChatMessage.svelte` 目前对 `tool_result` 无专用渲染（直接走 Markdown 显示 `[Tool xxx result]: ...` 文本）。
- `Cargo.toml` 的 tokio features：`macros, rt-multi-thread, time, sync`，**无 `process`**，需追加。
- assistant-mode 有 neuron 白名单 `tool_ids` 授权机制：neuron 需显式配置 `tool_ids` 含 `execute_command` 才可调用（既有机制，不改）。
- 日志规则（`.cursor/rules/logging-observability.mdc`）：shell 命令调用属关键节点，应打结构化日志，禁止记录完整命令输出/正文。

## Restated Understanding（已决决策）

1. **形态**：A —— Agent 工具（LLM 在 tool-calling 循环中自主调用），不做用户终端面板。
2. **范围**：仅 `packages/agent-app`（Tauri GUI）。
3. **安全策略 v1**：无强制用户确认；以「denylist + 超时 + 并发上限 + 输出截断 + 日志脱敏」兜底；用户确认机制列为 v2。

## 接口契约设计

### 工具定义

```
name: execute_command
description: 在用户系统上执行一条 shell 命令（sh -c / cmd /C），返回退出码、stdout 与 stderr。
parameters:
  type: object
  properties:
    command:     { type: string, description: "要执行的 shell 命令（原始字符串，交给系统 shell 解释）" }
    cwd:         { type: string, description: "可选。工作目录，缺省用进程当前目录" }
    timeout_ms:  { type: number, description: "可选。超时毫秒，缺省 30000，硬顶 120000" }
  required: [command]
```

### 返回格式（execute 返回的 String 为 JSON 文本）

```json
{ "exit_code": 0, "stdout": "...", "stderr": "...", "timed_out": false }
```

- 命令被 denylist 拒绝 / 参数非法：直接 `Err(AppError::InvalidInput(...))`。
- 超时：杀掉子进程，返回 `timed_out: true`、`exit_code: 124`。
- stdout / stderr 各自截断（默认上限 64KB，超出截断并标注）。

### 安全护栏（v1）

| 护栏 | 规则 |
|------|------|
| denylist | 命令去首尾空白后，命中危险前缀（`rm -rf /`、`mkfs`、`dd of=/dev/`、`shutdown`、`reboot`、`poweroff`、`halt`、`:(){`、`sudo` 等）→ 拒绝 |
| 超时 | `timeout_ms` 参数夹紧到 `[1000, 120000]`，缺省 30000；超时后 `child.kill()` |
| 并发 | 全局信号量（Semaphore，4 个许可）；许可耗尽时等待 |
| 输出截断 | stdout / stderr 各 64KB，超出截断并追加 `[truncated ...]` 标注 |
| 日志脱敏 | tracing 日志只记录 `command_len`、`cwd`、`exit_code`、`timed_out`、`duration_ms`、`stdout_bytes/stderr_bytes`；**不记录命令原文与输出正文** |

## 实现要点

1. **模块**：新建 `src-tauri/src/core/cmd_exec.rs`，导出 `ExecuteCommandTool`；`core/mod.rs` 声明 `pub mod cmd_exec;`。
2. **执行**：`tokio::process::Command`；shell 选择：`cfg(windows)` → `cmd /C`，否则 `sh -c`；`stdout/stderr` 均 `pip()` 捕获；`timeout` 用 `tokio::time::timeout` + `child.kill()`。
3. **依赖**：`Cargo.toml` tokio features 追加 `process`。
4. **注册**：`gateway.rs:84` 改为 `let mut tr = ToolRegistry::new(); tr.register(ExecuteCommandTool::new()); let tool_registry = tr;`（其余组装不变）。
5. **insert**：新建 `src-tauri/inserts/execute_command.md`，按仓库 insert 范式（`# <id>` / `## 工具` / `## 对模型的期待` / `## 忌用` / `## 注意`）。
6. **前端**：`ChatMessage.svelte` 增加 `msg_type === "tool_result"` 分支，解析 content 中 JSON 并渲染为等宽、可折叠的输出块（样式对齐 ToolCallBlock 的 oklch 深色终端风格）。
7. **测试**：`cmd_exec.rs` 单元测试覆盖——参数解析、denylist 拒绝、正常执行（`echo`）、非零退出码、超时（短超时）；`cargo test --lib` 通过。
