# 课题域（Topic）— 作用约定

> 本文件只约定课题域的**作用**：课题是什么、状态如何流转、待办如何管理、各方如何消费。不约束实现方式；实现变化不影响本约定。
> 来源 spec：[课题条目管理](../../micro_specs/2026-07-29_00-34_topic-scope-item-management.md)、[中文术语「课题」](../../micro_specs/2026-08-01_03-52_topic-zh-term-ke-ti.md)、[空待办收尾](../../micro_specs/2026-08-28_14-00_topic-empty-scope-close.md)。
> 实现参照（非约定，随时可换）：`core/topic_store.rs`（全部业务能力所在）、`core/topic_manager.rs`（**未装配的预留壳**，见 §8）。

## 1. 课题是什么

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**课题 = 一件需要多轮推进才能完成的事，带一份可勾选的待办清单。**

- 一句话描述目标（name + description）；
- 一组待办项（scope_in），每项 = 目标（goal）+ 验收标准（done_contract）+ 状态；
- 一个进度百分比与一个当前状态——**两者都不是手工填的，由待办状态推导**（§3）；
- 可选绑定一个会话（§5），可挂扩展数据（extra，助手态计数与复盘留痕住这里）。

课题域**只负责课题本身的事实记录**：谁创建、状态如何、待办如何。**谁推进课题、为什么推进，不归本域**——那是助手域与裁决 hook 的事。

## 2. 待办项（scope item）

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

每项待办：

| 字段 | 语义 |
|---|---|
| `goal` | 要做什么（非空） |
| `done_contract` | 怎么算做完（非空）——验收标准，勾选完成的依据 |
| `status` | `pending` 待办 / `completed` 已验收 / `blocked` 等待用户介入 |
| `blocked_reason` | blocked 时记录「用户需要做什么」；解除时清空 |

规则：

- 待办项有稳定 id，**按条目单条操作**（增 / 删 / 改 / 验收 / 标记阻塞），不存在整体替换——创建时一次性给初始清单之后，清单只能逐条变。
- 任何一条待办变化，**课题进度与状态同一次动作内自动重算**，不会出现进度过期。
- 删除或验收不存在的条目 → 明确报错；重复验收已完成的条目幂等。

## 3. 课题状态：两类，来源不同

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**推导态（由待办算出，不可手工指定）**：

| 状态 | 推导条件 |
|---|---|
| `todo` | 没有待办，或没有任何已完成项 |
| `in_progress` | 有已完成、也有未完成（pending）项 |
| `done` | 待办非空且全部已完成（进度 100%） |
| `waiting_user` | 没有 pending 项，但有 blocked 项（剩下的都在等用户） |

进度 = 已完成数 × 100 ÷ 待办总数（整数百分比）。

**人工态（人 / 流程显式设置，推导不覆盖）**：

| 状态 | 含义 |
|---|---|
| `paused` | 用户手动暂停：**一切待办变更被拒绝**（§6）；恢复时重新按待办推导 |
| `cancelled` | 保留的人工废弃态（当前入口命令无直接设置路径） |
| `wrapping_up` | 过渡态：待办已 100% 完成但最后一轮在调工具，等模型出最终总结——只由轮次复盘 hook 设置与关闭，存储层推导永远不会产出它 |

## 4. 待办生命周期约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

- **新增**：goal / done_contract 均非空，默认 `pending`。
- **编辑**：改 goal / done_contract（至少一项非空）；**编辑已验收项 → 自动重置为 pending**（契约变了，必须重新验收）。
- **验收**：标 `completed`。
- **标记阻塞**：标 `blocked` + 可选原因——语义是「需要用户做什么才能继续」。
- **解除阻塞**：用户介入后**一次性解除全部 blocked**（全部回 pending、原因清空）。此时：等待用户的课题恢复推导态、重新可被轮询；**用户手动暂停的课题只解除阻塞、保持 paused**（不自动复活）。
- **删除**：按 id 删条目。

## 5. 会话绑定约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

- **一个会话同时至多绑定一个课题**；把会话绑到第二个课题是错误。
- 同一课题重复绑同一会话幂等。
- 未绑定的课题可以被裁决切换走；绑定关系随创建时的裁决建立（见 [user_round_judgement](../hook/user-round-judgement.md)）。

## 6. 写保护与失败约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

1. **paused 是硬闸**：暂停期间待办的新增 / 删除 / 编辑 / 验收 / 标记阻塞一律失败，且不产生部分写入（单条动作原子生效）。
2. **创建后的通用更新入口只改名称 / 描述 / 扩展数据**——不接受改状态、待办、进度（防止旁路绕过推导）。
3. 创建时传入的状态仅 `paused` / `cancelled` 有效，其余一律按待办推导。
4. 操作不存在的课题 → 明确报错。
5. 任何写操作成功后，**统一广播一次变更事件**，监听方据此刷新，不逐入口自行通知。

## 7. 谁在消费课题（消费语义约定）

| 消费方 | 约定 |
|---|---|
| 用户轮裁决 hook | 创建 / 绑定 / 切换课题；读未完成课题清单供路由对照 |
| 轮次复盘 hook | 修订与验收待办（受「已完成项保护」门禁，见 [round-review](../hook/round-review.md)）；**待办被删空时直接结题**——空待办推导不出 done，若不收尾会被轮询永远空转，这条收尾责任在复盘 hook，不在存储层 |
| 自动轮询（Poller） | 推进未完成课题；**跳过 paused / cancelled / waiting_user**（等待用户的课题没有用户介入不得空转；blocked 项未解除前轮询不应推进该课题） |
| 简报推进 | 待办清单（含验收标准、阻塞原因）作为课题简报喂给模型 |
| 前端课题面板 | 全量 CRUD + 暂停 / 恢复 / 逐条待办管理；变更经广播事件刷新 |

## 8. 预留（未生效）

`topic_manager.rs` 中的模型工具适配器（list_topics / create_topic / …）**从未注册进工具链**——等自描述契约就绪再启用，当前所有入口是入口层命令（GUI 与远程 RPC 同名转发），直连存储能力。此文件不影响本约定任何一条。

## 9. 不变量（禁止事项）

1. 进度与推导态**只能**由待办状态推导得出，任何入口不得直写。
2. 一会话至多绑一课题。
3. paused 课题零待办写入。
4. blocked 是合法持久状态：重启、迁移后必须原样保留（等待用户的语义不能丢）。
5. 待办项必有非空 goal 与 done_contract——没有验收标准的待办不允许存在。
6. 待办变更与进度 / 状态重算在同一次动作内完成，不允许中间态可见。
