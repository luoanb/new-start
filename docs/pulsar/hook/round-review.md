# round_review — 轮次复盘（作用约定）

> 本文件只约定这个 hook 的**作用**：做什么、何时做、依据什么、结论如何生效、失败如何表现。不约束实现方式；实现变化不影响本约定。
> 来源：合并原「课题范围修订」与「进度验收」两个裁决（[2026-08-30 spec](../../specs/2026-08-30_10-30_hook-gating-merged-judgement.md)）。
> 实现参照（非约定，随时可换）：`core/hook/instances/round_review.rs`。

## 1. 作用

**在一轮工作自然收尾后复盘课题**，回答一个问题：**课题的待办与完成状态，经过这一轮之后应该变成什么样**。一次判断同时产出两类结论：修订待办（增 / 删 / 改）与验收勾选（完成 / 阻塞）。

## 2. 触发约定

- **时机**：一轮产物落定之后，复盘的是刚发生的这一轮。用户介入轮、手动推进轮、自动轮询轮均可触发。
- **只复盘"收尾轮"**：本轮既没声明也没执行工具（模型「说完了」而不是「干到一半」）才裁决；工具轮的中间产物不复盘。
- **暂停中 / 等待用户的课题不复盘**（状态不被改动）。
- **空待办的课题不裁决**：直接结题（无可推进事项，防止自动轮询空转）。
- **收尾中的课题**（已完成、等模型出最终总结）：不调模型，只看本轮——本轮纯文本收尾则正式结题，本轮仍在调工具则继续等。
- 复盘有实际动作时在对话中留**裁决卡**（判断中 → 结论），同用户轮裁决。

## 3. 判断依据（输入语义）

| 依据 | 语义 |
|---|---|
| 课题全量待办 | 含每项目的、验收标准、当前状态（待办/完成/阻塞及原因） |
| 本轮模型最终输出 | 干了什么、完成了什么的直接证据 |
| 本轮触发输入 | 用户消息或推进指令 |
| 触发方式 | 用户介入 / 手动推进 / 自动轮询（影响「已完成项保护」门禁的适用） |

判断由**当前对话所选模型**执行（与主对话同源）。

## 4. 判断结论（输出语义）

| 结论 | 语义 |
|---|---|
| `reason` | 本次复盘的理由（留痕用） |
| `add` | 新增待办：目标 + 验收标准 |
| `remove` | 删除待办：按 id |
| `update` | 修改待办：按 id，可改目标 / 验收标准 |
| `completed` | 勾选完成的待办 id |
| `blocked` | 勾选阻塞的待办 id + 各自原因（等待用户介入等） |

## 5. 行为约定（结论如何生效）

- **先修订、后验收**：新加的待办本轮即可被验收。
- **已完成项保护**：已勾选完成的待办，只有**用户亲自介入的轮次**才允许删改；自动/手动轮次只能跳过并留痕。
- **验收无轮次限制**：完成 / 阻塞勾选在任何触发轮次下都生效（与上一条是两个不同的门）。
- **单项容错**：任何一项修订/勾选失败只记日志，不影响其余项。
- **留痕约定**：有实际动作（含被门禁跳过的项）才在课题上记一条复盘事件（时间、触发方式、理由、各项明细）；**空复盘不留痕**。
- **收尾不跳步**：待办全部完成但本轮仍在调工具 → 课题进入「收尾中」状态、保持推进，模型下一轮输出纯文本总结后才正式结题。

## 6. 失败约定

- 模型复盘失败（带反馈重试一次后仍失败）→ **空操作**：不修订、不勾选、不留痕。
- 复盘失败**绝不影响本轮已产生的对话产物**（回复、消息、工具结果照常生效）。

## 7. 禁止事项（不变量）

1. 不修改对话消息本身。
2. 不动暂停中 / 等待用户的课题。
3. 非用户轮不删改已完成项。
4. 全部完成 + 工具轮必须走「收尾中」，不得跳过收尾直接结题。
5. 空复盘不留痕；复盘失败不阻断本轮。
