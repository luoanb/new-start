# user_round_judgement — 用户轮裁决（作用约定）

> 本文件只约定这个 hook 的**作用**：做什么、何时做、依据什么、结论如何生效、失败如何表现。不约束实现方式；实现变化不影响本约定。
> 来源：合并原「介入打分」与「课题匹配」两个裁决（[2026-08-30 spec](../../specs/2026-08-30_10-30_hook-gating-merged-judgement.md)）。
> 实现参照（非约定，随时可换）：`core/hook/instances/user_round_judgement.rs`。

## 1. 作用

**在用户介入的那一刻做一次判断**，回答两个问题：

1. **上一轮介入干得怎么样**——把用户本次介入解读为对**上一轮介入**的反馈：以本次介入与上一轮介入的**关联性**为前提，从关联中的意图（赞扬、不满、递进、纠错等）判断上一轮 AI（神经元）的执行情况，并给出分数；
2. **这个会话该归属哪个课题**——切去已有的（switch）、新建一个（create）、还是继续当前（continue）。

一次判断同时产出两个结论，一次模型调用完成。

## 2. 触发约定

- **时机**：**每轮用户介入都触发**——用户发来消息即判断，无论会话是否已绑定课题。
- 自动轮询推进、手动推进的轮次**不做**此判断。
- 每次判断在对话中留一张**裁决卡**：判断进行中显示「裁决中」，结束后显示结论与模型原始输出。

## 3. 判断依据（输入语义）

| 依据 | 语义 |
|---|---|
| 用户本次输入 | 待解读的消息：重点判断它与上一轮介入的**关联性**，以及关联基础上的意图（赞扬 / 不满 / 递进 / 纠错等） |
| 当前会话与课题绑定状态 | 路由分支的起点（打分仅在已绑定时生效） |
| 未完成课题清单 | 供 switch 对照（含名称、描述、状态、归属会话、进度、待办项） |
| 上一轮介入的参与神经元 | 打分对象：上次用户介入之后到本次输入之前，实际参与执行工作的神经元（去重） |

判断由**当前对话所选模型**执行（与主对话同源，不另读默认配置）。

## 4. 判断结论（输出语义）

| 结论 | 语义 |
|---|---|
| `score` | 对**上一轮介入**执行情况的评分：-5..5 整数。由本次介入与上一轮的关联性推导——有关联时按意图给分：赞扬、递进 → 正分，不满、纠错 → 负分，幅度反映意图强弱；**0 表示无关联 / 不打分**（越界、缺失同义） |
| `action` | `switch` 切去已有课题 / `create` 新建课题 / `continue` 继续当前课题 |
| `topic_id` | switch 的目标课题 |
| `name` / `description` | create 时的新课题名称与描述（可省略，省略有缺省规则） |
| `scope` | create 时的初始待办（每项 = 目标 + 验收标准），可为空 |

## 5. 行为约定（结论如何生效）

**打分**：

- 打的是**上一轮介入**的分：分数落在上一轮介入中实际参与执行工作的神经元上（仅限本会话，且会话已绑定课题时生效），作为对其执行情况的权重增减。
- score = 0（含与上一轮无关联）、越界、缺失一律视为「不打分」。

**路由**：

- **switch**：会话随课题走——目标课题绑定在哪个会话，当前轮就切到那个会话继续；目标课题未绑定时绑到当前会话。目标课题不存在时，按结论中的名称/描述/待办**新建兜底**（待办也缺失时，用用户输入构造一条「目标待确认」的兜底待办）。
- **create**：会话已有课题时**忽略**（一个会话同时只绑一个课题）；新建后立即绑定当前会话。名称缺省 = 用户输入前 40 字符，描述缺省 = 用户输入。
- **continue**：未绑定的会话不允许 continue（契约违反），与 create 同路兜底。
- **结论不明（降级）**：**绝不默认创建课题**。已绑定则保持现状；未绑定则向对话写一条明确提示（"助手模式必须绑定课题……下一条消息将重新裁决"），下一条用户消息重新判断。

**边界**：会话切换是本 hook 对对话流的**唯一**改写；用户输入与历史消息内容永不被本 hook 修改。

## 6. 失败约定

- 模型判断失败（带反馈重试一次后仍失败）→ 采用**中性结论**：不打分、路由不动。主对话正常继续，**绝不因裁决失败中断用户介入的轮次**。
- 未绑定会话遇失败：按「结论不明」处理（提示 + 下一条重新判断），保证"会话必须绑定课题"的约束始终被看见而不是被静默放过。

## 7. 禁止事项（不变量）

1. 不修改用户输入、模型回复等任何对话内容。
2. 不跨会话打分：只对本会话参与过的神经元打分。
3. 不在结论不明时默认创建课题。
4. 一个会话同时至多绑定一个课题。
5. 裁决失败不阻断主轮次。
