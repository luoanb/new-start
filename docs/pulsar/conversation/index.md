# 会话域（Conversation，轮次管线）— 作用约定

> 本文件只约定会话域的**作用**：一轮对话如何走完、真相源与落库语义、并发协调、上下文安全、三种模式、压缩。不约束实现方式；实现变化不影响本约定。
> 实现参照（非约定，随时可换）：`core/conversation_store.rs` / `conversation_runner.rs` / `round_types.rs` / `round_resolver.rs` / `round_executor.rs` / `session_coordinator.rs` / `context_safety.rs` / `chat_session.rs` / `agent_session.rs` / `compactor.rs`。

## 1. 域是什么

**会话域 = 把"用户说一句话"到"AI 回复落定"变成一条可复现的流水线。**

它管四件事：**会话与消息的真相源**（存什么、什么时候存）、**一轮的统一流程**（固定管线）、**并发秩序**（一个会话同时只有一轮）、**上下文安全**（任何东西进上下文前先变可控）。模式差异（Chat / Agent / Assistant）与业务副作用（课题、打分）**不属于本域**——它们是挂在这条管线上的业务层。

## 2. 真相源约定（先落库，再使用）

- **消息历史是唯一真相**：管线内全程使用与落库同构的消息形态，发送前才投影为线上格式。不存在"另一份中间态历史"。
- **先落库再发送**：用户输入、角色上下文、推进指令在**调模型之前**全部落库——模型调用失败、超时、被抢占，**用户消息与已落库内容都不丢**。
- **落库即增量**：每轮落库只写本轮新增的消息（角色上下文 / 输入 / 模型声明 / 工具结果 / 回复），不重写历史。
- **模型声明与执行结果分开落**：模型声明了工具调用 → 声明先落库（不依赖工具执行成功）；工具结果再落库。"模型说过什么"与"工具跑出什么"是两类事实。
- **产物盖章**：本轮选中了哪个角色（神经元），随回复落库留痕——评分、审计据此推导，不另设跨轮状态。
- **读端与写端分离**：写端全量保证一致；读端支持会话摘要分页与消息倒序切片，长会话不全量拉取。

## 3. 一轮的统一管线约定

每一轮（无论谁触发）走同一条固定流程：

```text
装载上下文（读真相源 + 组装本轮参数）
  → 调度注入点（选型 / 课题路由等，见 Hook 域；可切换会话，切换后重载继续）
  → 构造输入消息 → 输入落库
  → 上下文注入点（压缩等，只影响本轮发送，不动真相源）
  → 模型调用 → 响应注入点 → 声明落库
  → 工具执行 → 结果注入点 → 产物落库
  → 收尾注入点（只读，副作用自办）
```

约定：

- **触发类型四种**：用户介入 / 手动推进 / 自动轮询 / Agent 循环。管线感知触发只到"输入怎么落库"为止，业务语义（课题、评分）由注入点 hook 承担。
- **会话切换可发生在最早的注入点**：调度 hook 改写会话后，管线**重载新会话**继续走——后续所有步骤基于新会话，已落库消息数推导的增量边界保持正确。
- **注入点契约与失败策略**（fail / ignore 梯度）归 Hook 域约定，此处只约定挂载位置。
- **流式**：同一管线有流式形态——增量按节流写盘与推事件（首块立发、约 150ms 一拍、完成时最终写保证一致），完成后消费方以全量重拉收敛。

## 4. 并发秩序约定（用户优先）

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**同一会话同一时刻只有一轮在跑。** 由会话级协调器保证：

| 新轮到达时 | 行为 |
|---|---|
| 已有轮在跑，新轮是**用户介入** | **抢占**：协作式取消旧轮；旧轮"回复多少存储多少"收敛落库；新轮**等旧轮收敛完成**后再取消息快照（保证新轮上下文包含旧轮的最终落库内容，而非写盘中间态）；等待有超时兜底，异常不悬挂 |
| 已有轮在跑，新轮是轮询 / 手动 / Agent 循环 | **跳过本轮**（静默，不打断进行中的对话） |
| 停止按钮（外部中断） | 与用户抢占同一套取消语义 |

- 取消是**协作式**的：被抢占轮在模型流式 / 工具执行两个等待点感知取消，执行收敛写。
- 忙状态**必然释放**：轮次占用以作用域守卫持有，任何早退路径（出错、返回、取消）自动释放，不遗留"永远忙碌"。

## 5. 上下文安全约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

背景是一条真实事故链：超大工具结果 → 上下文超限 → 轮询无限空转。防线约定：

- **工具结果必须上下文可控**：各工具自带上限（第一道）；落库与拼输出前的**统一兜底截断**（第二道）——超限结果按头尾保留截断，**附引导提示**（告诉模型用更精确参数重试，而不是静默丢内容）。
- **轮询熔断**：同一会话连续失败达到阈值 → 指数退避（封顶）；再失败 → 熔断暂停轮询，需人工恢复。连续成功即恢复。
- 阈值均可配置，未配置回落内置默认。

## 6. 三种模式约定（业务接入形态）

| 模式 | 形态 | 约定 |
|---|---|---|
| **Chat** | 单轮直调 | 无选型、无工具、无业务 hook——管线的退化形态 |
| **Agent** | 工具循环 | 授权注册表全部工具；循环推进直到模型不再调工具（收敛）；**循环轮数硬上限**（超限报错）；首轮落用户消息，后续轮只注入继续指令不重复落库 |
| **Assistant** | 业务编排 | 模式门控 / 课题解析 / 简报推进等业务逻辑与课题副作用 hook（约定见 Assistant 域与 Hook 域文档） |

## 7. 压缩约定

- **语义**：上下文接近模型窗口上限时，把旧消息生成一份摘要、其余本轮发送时跳过——**只影响本轮发送，永不删除真相源**。
- **估算口径**：混排文本按 ASCII ≈ 4 字符 1 token、非 ASCII ≈ 1 字符 1 token 估算（纯 chars/4 会系统性低估中文）。
- **两个入口**：用户手动压缩；自动压缩（挂载在管线的上下文注入点，每轮发送前判断，阈值 = 模型声明窗口 × 比例，未声明窗口回落默认）。
- 摘要本身也是消息，落库留痕，后续轮投影时跳过其覆盖的旧消息。

## 8. 失败约定

| 失败 | 表现 |
|---|---|
| 模型调用失败 / 超时 | 用户消息已在库（§2），错误驻留进对话（有解释，不留"无回复的用户消息"）；轮询路径计入熔断计数 |
| 被抢占 / 用户停止 | 已产出部分"回复多少存储多少"，不丢已生成内容 |
| 非用户轮遇忙 | 静默跳过本轮，不算失败 |
| 工具结果超限 | 截断 + 引导提示，不中断轮次 |
| 存储失败 | 明确报错；组合写操作在锁保护下串行，不出现交错丢写 |

## 9. 不变量（禁止事项）

1. 真相源只有一份：落库的消息历史。任何"中间态历史"不允许存在。
2. 用户消息必先落库再调模型——任何路径不得先发送后落库。
3. 一个会话同时至多一轮在跑；用户介入永远可抢占。
4. 压缩永不删除或改写真相源消息。
5. 工具结果进上下文前必经截断兜底；无"原样超大结果入库"路径。
6. 模型声明与工具执行结果是分开的事实，落库不合并。
7. 业务语义（课题 / 评分 / 模式差异）不进管线本体——管线只认触发类型与注入点。
