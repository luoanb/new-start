# Provider 域 — 作用约定

> 本文件只约定 Provider 域的**作用**：模型调用入口的语义、服务商与模型的治理规则、参数抹平与合并、配置编辑与热重载、失败表现。不约束实现方式；实现变化不影响本约定。
> 实现参照（非约定，随时可换）：`core/providers.rs`（整合层）、`core/openai_compat.rs`（协议层）、`core/model_call_input.rs`（消息拼装工具）、`core/models.rs`（类型）。

## 1. 域是什么

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**Provider 域 = 把"调一个模型"变成一件可以不问服务商的事。**

对外只有一件事：给它（服务商, 模型, 消息列表, 可选参数），拿回模型的回复。至于这家服务商的地址、密钥、协议怪癖、思考模式怎么开、参数怎么合并——全部由本域内部处理。

内部两层分工（职责约定）：

| 层 | 负责 | 不负责 |
|---|---|---|
| **整合层**（providers） | 服务商/模型治理、密钥与地址解析、参数合并抹平、调用编排、配置管理面 | 协议序列化 |
| **协议层**（openai_compat） | OpenAI Chat Completions 协议的编解码、HTTP 发送、SSE 流式解析 | 任何服务商策略与能力判断 |

分层铁律：协议层**不含**任何服务商策略；整合层**不碰**协议编解码。服务商特有参数（reasoning_effort、thinking 开关等）以"透传字段"方式过协议层，由整合层按需填充。

## 2. 模型调用约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**入口语义**：一次调用 = （服务商 id, 模型 id, 消息列表）+ 三类可选单次覆盖（采样参数、思考模式、结构化输出契约）。返回 = 文本输出 + 工具调用列表 + 结束原因 + 思维链。同步与流式两种形态，流式逐块回调、最终聚合出同一形态的结果。

**调用前置校验**：

- 服务商与模型 id 非空、消息列表非空；
- 消息正文非空——唯一例外：assistant 消息携带工具调用记录时允许空正文（OpenAI 兼容规范的合法形态）；
- 服务商必须在运行集中，模型必须已登记（声明"允许未登记模型"的服务商除外，§3）。

**密钥与地址解析优先级**：环境变量 > config.json > 代码内置默认地址。密钥缺失且该服务商必填密钥时，明确报错并**指明**应设置哪个环境变量或哪个配置文件。

## 3. 服务商治理

- **内置服务商**（定义在代码里）：openai、deepseek、ollama、custom。**永不物理删除**——"删除"内置 = 标记禁用，代码定义保留，随时可重新启用。
- **自定义服务商**：存于配置文件，删除即移除。
- 禁用的服务商从运行集隐藏：不可调用、不出现在可选列表；编辑视图中仍可见（便于重新启用）。
- "允许未登记模型"是服务商级开关（ollama / custom 默认开）：开启后调用未在模型注册表登记的模型不报错，能力按未知处理（§5）。
- API Key **永不回显明文**：编辑视图一律掩码；保存时收到掩码或空值 = "未修改"，保留原值，只有非掩码新值才覆盖。

## 4. 模型注册表

每个登记的模型是一份**声明**：

| 声明 | 谁消费 |
|---|---|
| 能力（chat / tools / streaming / structured_output / vision / audio） | 结构化输出降级链、工具授权决策 |
| context_window（token） | 自动压缩的阈值估算；未声明时消费方自行回落默认 |
| 默认采样参数、默认思考模式（是否开、强度） | 每次调用的参数合并底座（§5） |
| max_output_tokens、价格、知识截止 | 展示与成本估算 |

**声明即真相**：本域不探测、不猜测模型能力——没声明的视为没有。查询接口对未登记模型返回"未知"，由调用方决定回落值。

## 5. 参数抹平与合并（每次调用）

**优先级：调用级单次覆盖 > 模型定义默认。** 未设置的字段逐项取低层值，不做整体覆盖。

**思考模式抹平**（本域替调用方兜底）：

1. 模型未声明支持思考 → 一律关闭（调用方开了也无效）；
2. 调用级未指定开关/强度 → 用模型声明的默认；
3. 思考未开启时不携带强度参数。

思考参数的线上形态：OpenAI 标准字段 + 服务商特有开关（如 DeepSeek 的 thinking）一并透传。

**结构化输出契约**：调用级传入则按官方 Structured Outputs 线上形态下发；不传 = 无约束。

## 6. 请求 / 响应契约

**多轮工具调用回传**：assistant 消息带工具调用记录时，必须随消息回传其思维链（reasoning_content）——部分推理模型不回传会直接拒绝请求。本域负责把这个字段带上线上。

**思维链出参**：推理模型的思考过程作为回复的一部分返回给调用方（流式下聚合后同源），"只有思维链没有正文"对推理模型是正常行为。

**空响应防御**：HTTP 成功但回复里既无文本、无工具调用、也无思维链 → 判为异常返回错误（附 finish_reason、用量、原始请求摘要等诊断信息），**绝不把空消息落进对话历史**（空 assistant 消息会锁死后续轮次）。

## 7. 配置编辑约定

- **整体读写**：编辑视图 = 默认模型对 + 服务商清单（含各自模型清单）一次取全、一次存全；不做字段级 patch。
- **保存链路**：校验 → 原子写回 → 热重载 → 返回保存后的视图。**保存即生效，无需重启**；进程内按配置代数缓存的探测结果（如能力探测）在写盘后自然失效。
- **校验规则**：服务商 id 非空、仅限字母数字下划线连字符、不得重复；模型 id 非空；默认模型必须指向**已启用**服务商下**已登记**的模型，且 provider/model 必须成对配置。
- **写入边界**：只写 `defaults` / `providers` 两个配置键，配置文件里的其他键（轮询、课题、服务商以外的任何段）原样保留。
- 配置文件非法或读取失败**不阻断启动**：回落内置服务商全集继续运行。

## 8. 消息列表拼装（辅助约定）

模型调用前的消息列表手术是本域的纯函数工具，供轮次管线消费：

- **替换系统提示**：替换第一条 system 或前插；空系统提示不产生空 system 消息（线上会拒），只清除遗留的空 system、保留非空的（如压缩摘要）。
- **拼接模板**：角色/能力载体模板（神经元语义）与操作说明书模板（工具契约语义）两种内置追加模板。
- **工具消息成对净化**：发送前修复悬空的工具调用/结果消息，避免部分服务商因不成对消息报 400。
- **历史投影**：把落库消息投影为线上消息；被压缩摘要覆盖的旧消息跳过（压缩语义归 Conversation 域）。

所有手术**不改入参**，返回新列表。

## 9. 失败约定

| 失败 | 表现 |
|---|---|
| 密钥缺失（必填服务商） | 明确错误，指明环境变量名与配置文件路径 |
| 未登记模型（服务商未开允许） | 明确"模型不存在"错误 |
| 消息校验失败 | 请求发出前拦截，明确指出哪条消息不合法 |
| 上游 HTTP/协议错误 | 归一为统一的模型调用失败错误（带上游信息），调用方无需理解各服务商差异 |
| 空响应 | 按异常处理（§6），附诊断信息 |
| 配置非法 | 保存前校验拦截；启动期读盘失败回落内置全集，不阻断 |

## 10. 不变量（禁止事项）

1. 协议层不含服务商策略；整合层不做协议编解码。
2. 内置服务商定义永不物理删除。
3. API Key 永不明文回显；掩码/空写回 = 保留原值。
4. 保存只触碰 `defaults` / `providers` 两个键。
5. 能力以声明为准：本域不猜测、不探测模型能力。
6. 空响应永不进入调用方的对话历史。
7. 默认模型对必须指向已启用服务商的已登记模型。
