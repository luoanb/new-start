# 助手域（Assistant）— 作用约定

> 本文件只约定助手域的**作用**：助手模式的业务编排、课题简报与轮次计数、后台轮询、运行态跟踪。不约束实现方式；实现变化不影响本约定。
> 课题语义归 [Topic 域](../topic/index.md)，裁决与副作用归 [Hook 域](../hook/index.md)，轮次管线归 [Conversation 域](../conversation/index.md)——本域是把这些粘成"助手模式"的业务层。
> 实现参照（非约定，随时可换）：`core/assistant_session.rs` / `poller.rs` / `poller_step.rs` / `session_tracker.rs`。

## 1. 域是什么

**助手域 = 让"一个会话围绕一个课题自主推进"成立的那层业务。**

用户说一句话 → 判断归哪个课题 → 课题简报告诉 AI 现在干什么 → AI 推进 → 复盘勾待办 → 没干完的话后台轮询接着推。本域负责这条业务链上的**编排**：模式门控、课题解析、简报推进、轮次计数、后台轮询、运行态跟踪。判断（裁决）由 hook 承担，管线由会话域承担——本域不重复造这两样。

## 2. 一轮的业务编排约定

助手模式下，一轮的前后由本域编排（经业务 hook 挂进管线）：

- **模式门控**：课题副作用只在助手/系统模式发生；Chat、Agent 模式零介入。
- **轮前**：
  - 解析会话绑定的课题（会话 ↔ 课题约定见课题域）；
  - 用户介入时：解除"等待用户"状态（阻塞的待办全部恢复为待办，课题恢复轮询——约定见课题域 §4）；
  - 用户介入轮执行**用户轮裁决**（打分 + 路由，约定见 [user_round_judgement](../hook/user-round-judgement.md)）；手动/轮询推进轮改为**推进简报**。
- **轮后**：执行**轮次复盘**（约定见 [round-review](../hook/round-review.md)）+ 推进轮次计数（§4）。
- **错误驻留**：用户轮失败时向对话写一条明确的错误说明——**不留"无回复的用户消息"**。

## 3. 课题简报约定

**简报 = 每轮告诉 AI"课题现在什么样、这轮干什么"的指令。**

- **内容形态**：课题名 / 目标 / 进度百分比 / 待办清单（每项带验收标准；已完成标验收、阻塞项标"等待用户"并附需要什么）；收尾中的课题改为"输出最终总结、无需调工具"。
- **刷新时机（三条件任一）**：课题有变化（待办/状态变了）· 上轮以工具调用结束（干到一半，局面变了）· 距上次刷新达到频率阈值。其余轮复用缓存简报。
- **生成一次、进 wire 一次**：简报刷新时构造为推进消息落库（历史自带上一份简报），复用缓存的轮次不重复构造——简报不重复灌历史。
- 手动推进必须已绑定课题（没有课题就没有简报依据）。

## 4. 轮次计数约定

课题上维护三类计数（作为各低频机制的频率基准）：

| 计数 | 语义 |
|---|---|
| 总轮数 | 每个成功跑完的轮 +1 |
| 用户介入轮数 | 用户介入轮 +1；**同时**把"距上次介入的推进轮数"清零 |
| 推进轮数 | 手动/轮询推进轮 +1 |

约定：计数只在**轮成功完成后**推进；失败轮不计数（熔断走自己的通道，§5）。"每 N 轮做一次某事"的低频机制（简报刷新、裁决复核、选型降频）都以此为基准，数值归各机制自己的约定。

## 5. 后台轮询约定

- **调度形态**：定时器 tick → 全量推进请求（不阻塞 tick 循环）→ 遍历所有未完成课题，受限并发推进（并发数运行时可调，有硬上限）。
- **节奏**：基础间隔 × 每 N 个 tick 推进一轮；全部可配置。
- **跳过规则**：暂停中、已取消、等待用户的课题**不推进**（等待用户的课题没有用户介入不得空转——与课题域约定闭环）；遇会话忙按管线规则跳过。
- **失败退避与熔断**：同一会话连续失败达到阈值 → 指数退避（跳过的 tick 数封顶）；再连续失败 → **熔断暂停该会话轮询**，需人工恢复；用户手动推进成功即视为恢复探测成功。
- **轮询失败不丢产物**：推进失败的轮按管线错误驻留语义处理，不打断其他课题的推进。

## 6. 运行态跟踪约定

- **运行中会话清单**：内存态跟踪当前在跑的会话（开始时间、当前步骤），供前端展示与"正在运行"判定；变更即通知。
- **注册归属**：每轮注册拿到归属句柄，收尾凭句柄注销——旧轮被抢占后其过期句柄**不会误删**新轮的登记。
- **强制停止**：关闭会话 = 外部取消该会话活动轮次（取消语义与用户抢占一致，见会话域 §4）。
- （AI 可见"哪些会话在跑"的查询工具已预留、未注册生效。）

## 7. 失败约定

| 失败 | 表现 |
|---|---|
| 用户轮模型失败 | 错误驻留进对话（§2），计入该会话熔断计数 |
| 轮询轮失败 | 同上 + 连续失败退避/熔断（§5）；其他课题推进不受影响 |
| 遇忙跳过 | 静默，不算失败不计熔断 |
| 手动推进无绑定课题 | 明确报错（简报无依据） |
| 复盘/裁决 hook 失败 | 按各 hook 约定降级，不影响本轮产物落库 |

## 8. 不变量（禁止事项）

1. 课题副作用只发生在助手/系统模式；Chat 与 Agent 模式零课题介入。
2. 计数只记成功轮；失败轮不推进任何计数。
3. 简报落库遵循"生成一次、进 wire 一次"，不重复灌历史。
4. 等待用户的课题不得被轮询推进；只有用户介入能解除等待状态。
5. 熔断必须"连续失败触发 + 可配置 + 可人工恢复"，不允许误伤一次失败。
6. 会话运行态注册不允许过期句柄误删新轮登记。
