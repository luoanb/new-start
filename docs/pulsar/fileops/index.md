# 文件领域（FileOps）— 作用约定

> 本文件只约定文件领域的**作用**：工作区边界、文件操作护栏、覆盖保护、Git 能力、语义搜索。不约束实现方式；实现变化不影响本约定。
> 实现参照（非约定，随时可换）：`src-tauri/src/fileops/`（workspace / fs / fs_tools / gitops / search）。

## 1. 域是什么

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**文件领域 = 应用触碰用户文件系统的唯一通道。**

所有"看文件、改文件、跑 git、搜代码"——无论来自 AI 工具还是前端界面——都走这一层、共用同一套护栏。**不存在绕过护栏的第二条路径**：AI 工具与前端 UI 看到的是同一个工作区集合、受同一套边界约束。

三块能力：工作区内的文件操作（§2-§4）、Git 操作（§5）、语义搜索（§6）。

## 2. 工作区约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

- **工作区是唯一的操作边界**：每个工作区 = 一个规范化后的根目录 + 独立的文件树过滤规则（ignore）。工作区清单持久化，跨重启保留；同一目录重复添加自动去重。
- **当前工作区**：有一个"活动工作区"概念——AI 文件工具不传根目录，隐式作用于活动工作区。
- **默认过滤规则**：新工作区自带一组默认 ignore（.git / node_modules / target / dist / build / out / coverage / .pulsar / .DS_Store），用户可改——意义是**构建产物与依赖目录默认不进 AI 视野**（防止把 3MB 的压缩产物整行读进上下文）。
- **越界护栏**：所有路径必须是工作区内相对路径；绝对路径、包含 `..` 逃逸、符号链接解析后越出根目录——一律拒绝。目标尚不存在时按最近存在祖先解析再拼接（新建文件同样受边界约束）。

## 3. 文件操作约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

操作集合：列目录、读、写、查找替换、删除、glob、grep、文件信息、建目录、重命名/移动。统一护栏：

| 护栏 | 约定 |
|---|---|
| 读上限 | 单次读取超防御上限拒绝（防拉爆内存）；默认按阈值分块，支持行级 offset/limit 翻页 |
| 写上限 | 单次写入超上限拒绝 |
| 二进制 | NUL 字节启发式判定为二进制 → 拒绝读为文本 |
| grep | 结果条数、单行长度、上下文行数三重上限（防产物文件/压缩文件灌爆） |
| glob | 结果条数上限，按修改时间排序 |
| 过滤 | 列目录 / glob / grep / 索引全部遵守工作区 ignore 规则 |

## 4. 覆盖保护约定（防丢改动）

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**核心规则：覆盖一个已存在的文件之前，必须证明"你看到的版本就是磁盘上的最新版本"。**

- **AI 路径**：`read` 时登记"已读"快照；未读过的文件不允许覆盖写；查找替换同样要求先读。
- **前端路径**：编辑器打开文件时拿到版本快照，保存时携带——语义相同。
- **冲突检测**：写入时磁盘修改时间 ≠ 读时的快照 → 拒绝并要求重新读取（防止盖掉别人的改动）。
- **写入即快照**：成功写入后更新快照，连续编辑无需重复读取。
- 文件写入后**通知 git 状态刷新**（面板徽标与 AI 视角同步）。

## 5. Git 约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

**"用户命令行里的 git"是唯一真相**：git 能力通过调用系统 git CLI 实现，参数不经 shell 拼接；行为与用户手动跑 git 完全一致——本领域不发明 git 语义。

- **仓库发现**：在活动工作区内发现仓库（含嵌套仓库标记），有"活动仓库"概念。
- **两级工具授权**：
  - **只读 6 个**（status / diff / log / branch / blame / stash_list）→ 常驻 Core 组，随主对话可用；
  - **写 9 个**（add / restore / commit / reset / checkout / stash / push / pull / 冲突解决）→ 按需授权，且其中**破坏性操作受两道闸**（下）。
- **确认闸**：恢复改动、提交、推送、拉取等写操作 → 先进入待确认队列并向用户广播确认请求，用户批准才执行；**60 秒不确认自动作废**。
- **危险开关闸**：丢弃工作区改动的操作（hard reset、丢改动的 checkout）在确认之外**另受"危险写入"总开关约束**——开关默认关闭，关闭时这类操作直接拒绝。
- **状态视图**：status 以逐文件粒度展示（未跟踪目录展开为具体文件，不做目录聚合），含分支、领先/落后远端计数。

## 6. 语义搜索约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

- **块级而非行级**：与 grep 的本质差异——按语法单元（函数 / 结构体 / 类 / impl / 接口）整块返回，行级工具给"匹配的行"，语义搜索给"完整代码块"。未知语言回退启发式分块。
- **本地实现，不调 LLM**：关键词召回（FTS5 + bm25 + 块类型加权）；英文前缀匹配、中文按 2-gram 子串匹配；短查询严格 AND、长查询自动放宽 OR。
- **索引不污染用户项目**：索引存在应用自己的数据目录（按工作区根派生隔离键），不写入用户仓库。
- **增量构建**：按文件修改时间/大小增量更新索引；超大文件跳过索引；对外返回带行号与块类型的摘要片段。
- **暴露形态**：既是 AI 工具（语义搜索），也是前端命令。

## 7. 失败约定

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

| 失败 | 表现 |
|---|---|
| 路径越界 / 绝对路径 / `..` | 拒绝，明确"越出工作区根" |
| 覆盖未读文件 / 冲突 | 拒绝，要求先读 / 重新读取 |
| 上限类（读写大小、结果条数） | 拒绝并告知上限值 |
| git 确认超时 | 操作作废（不入 pending 重放） |
| 危险写入开关关闭 | 直接拒绝该操作 |
| git 本身失败 | 透传 git 的错误信息（用户的 git 说什么就是什么） |

## 8. 不变量（禁止事项）

> 🔒 用户盖章（2026-09-04）· 本节经用户确认冻结：未经用户明确确认，不允许调整对应代码与修改本节文档。

1. 本领域是文件系统的唯一通道，任何其他域不得直接读写用户工作区。
2. AI 工具与前端 UI 共用同一工作区集合与护栏，不允许任何一方有特权旁路。
3. ignore 规则在所有枚举/检索路径上一致生效。
4. 覆盖保护不可绕过：没有"强制写"选项。
5. git 行为不偏离用户 CLI git；写操作必须过确认闸，破坏性操作必须同时过危险开关。
6. 搜索索引永不写入用户项目目录。
