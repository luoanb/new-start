# 需求边界
1. NeuronCallService需要调整
2. 聊天主链路的调用，以及后续其他业务调用都需要切换到NeuronCallService

## 调整策略
1. 所有神经元都可以发起会话，NeuronCallService允许使用任意《神经元》发起会话（NeuronCallService提供默认行为：领域）
2. 不传神经元也能发起会话（全域神经元找到第一轮<神经元>后，后续按照领域推进）
3. <系统神经元>属于特例：允许不走默认行为，而是自主选型（无，固定，领域（不会有全域））;系统神经元在项目的定位是：服务于项目的指定场景的提示词
（每一次对话都需要选定属于自己的《神经元》， 下一次对话的<神经元>的选择为上一次对话的<领域>）

## 语义分离
1. 感觉不需要NeuronCallService， NeuronManager 内置一个NeuronCallModel:用于处理附带神经元的模型调用
