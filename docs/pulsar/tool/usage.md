# 工具使用层 — 作用约定

> 使用层约定"一轮对话如何授权与执行工具"。注册层（来源 / 门禁 / 声明 / 外部接入）见 [registration.md](./registration.md)。
> 实现参照（非约定，随时可换）：`core/round_executor.rs`（授权落点与执行）、`cmd_exec.rs`（命令护栏）、`mcp.rs`（调用有界）。

## 1. 授权决策（本轮带哪些工具）

- **授权是逐轮决策**，落点在执行侧。本轮授权清单的来源优先级：

  ```text
  调用方覆盖（如 Agent 模式全量授权）
    → 选中角色自带的工具清单
    → 按会话模式并入标签组
    → 最后与注册表求交（登记过才算数）
  ```

- **core 工具始终在场**：不管选了谁、什么模式，打了 core 标记的工具都出现在本轮请求里，不可被排除。注意分层：标签在注册层只是无语义的分组标记（见 [registration.md §3](./registration.md#3-标签仅是分组标记)），"core 组常驻、不可排除"是**本层赋予该分组的授权策略**，不是标签的固有属性。
- 授权决定只影响"本轮声明哪些工具给模型"，不影响工具登记（注册层事实不变）。
- 授权同时决定工具声明进请求——模型只能调用本轮声明过的工具。

## 2. 执行约定

- **单个工具失败不拖垮整轮**：执行异常时，错误作为该工具的结果返回给模型（模型可自行调整参数重试），轮次继续。
- **结果上下文可控**：工具结果进上下文前有统一截断兜底（超限按头尾保留 + 引导模型用更精确参数重试，不静默丢内容）——与各工具自带上限构成两道防线（轮次管线侧的完整约定见 [Conversation 域 §5](../conversation/index.md#5-上下文安全约定)）。
- 结果按工具调用 id 与声明配对返回，落库与配对语义归轮次管线。

## 3. 命令执行护栏

一切"跑命令"（AI 的 execute_command、配置的命令模板工具）共用同一套护栏，**没有豁免**：

- **拒绝清单**：灾难性命令前缀直接拒绝（毁盘、fork 炸弹、全盘提权等）；提权 / 关机类命令（sudo、shutdown 等）按词边界拒绝（不误伤普通词）。
- **走真终端**：命令在 PTY 会话中执行（约定见 [Terminal 域](../terminal/index.md)）——输出实时可见、行为与用户手敲一致，不存在绕过事件流的静默执行路径。
- **资源有界**：调用方要求的超时被夹紧到允许区间；同时执行数有上限；输出超限截断；敏感信息不进日志。

## 4. 外部工具调用有界

- MCP 工具单次调用有超时；结果文本超限截断后返回。
- server 级失败（连接断开）表现为该 server 工具不可用，不影响本地工具与其他 server。

## 5. 使用层失败约定

| 失败 | 表现 |
|---|---|
| 调用未授权 / 不存在的工具 | 明确错误以工具结果形态返回给模型，不中断轮次 |
| 命令命中拒绝清单 | 拒绝执行，明确告知禁止 |
| 命令超时 | 夹紧超时后终止，返回已产出输出与超时说明 |
| 工具执行异常 | 错误作为该工具结果返回，轮次继续（§2） |
| 结果超限 | 截断 + 引导提示，不中断轮次 |

## 6. 使用层不变量（禁止事项）

1. 模型只能调用本轮声明过且登记在册的工具——不存在"凭空调用"路径。
2. core 工具在任何会话中不可被排除。
3. 一切命令执行必过拒绝清单与护栏——配置声明工具没有豁免。
4. 单个工具失败不得拖垮整轮对话。
5. 工具结果进上下文前必经截断兜底；无"原样超大结果"路径。
