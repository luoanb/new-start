# Requirements / 需求文档: 神经元自举与工具契约

## Restated Understanding / 需求复述

本迭代独立收束神经元的数据模型、管理能力、模型调用、自举创建、候选选择和工具权限，是 `docs/sdd-lab/2026-07-26_21-30_assistant-mode/` 的前置需求。

核心目标：

- 神经元普通内容更新与权重调整分离，避免通用更新接口任意覆盖权重。
- 神经元管理能力初始化时注入 `call_model`，供内部创建和补齐流程私用。
- 神经元能够通过 `system_type=create_neuron` 的系统节点完成自举，并持续创建其他神经元。
- 提供按来源和权重选择固定数量神经元的统一能力，候选不足时自动创建补齐。
- 明确哪些能力属于内部能力、AI 工具和人类管理入口。
- 神经元持久化自身允许使用的工具 ID，供后续 Assistant 按神经元控制工具权限。

## Prerequisites And Dependents / 前置与下游

- 本迭代依赖现有系统工具注册表和 `call_model` 基础能力，但不改变 Provider 的业务职责。
- Assistant 运行模式依赖本迭代；本迭代需求确认并实现前，Assistant 不应固化神经元选择、神经元工具权限或相关 Hook 的最终实现。

## Scope / 范围

### In

- 调整神经元普通更新能力，使其只允许更新 `desc` 和 `content`。
- 新增权重增减能力，通过正负 delta 调整现有权重，不提供普通 AI 任意覆盖绝对权重的入口。
- 新增“创建下游神经元”能力：创建新神经元并建立 `source → new_neuron` 连接。
- 神经元管理能力初始化时必须接收可调用的 `call_model` 依赖。
- 神经元新增 `system_type` 字段和允许使用的工具 ID 集合。
- 建立 `system_type=create_neuron` 系统节点的发现、内部创建、缓存和失效恢复规则。
- 从配置读取“创建 `system_type=create_neuron` 系统节点”的提示词规则。
- 定义读取创建系统节点并调用模型创建其他神经元的内部能力。
- 定义按权重获取指定数量神经元的统一能力，支持可选 `source_id`、`system_type` 和 `min_new`，并允许 AI 与人类调用。
- 课题匹配等 Hook 所需提示词节点可以通过其他唯一 `system_type` 关联。
- 划分内部能力、AI 工具和人类管理入口。

### Out

- Assistant 对话、步进和系统轮询实现。
- beforehook/afterhook 的具体编排实现。
- Provider、模型协议或 `call_model` 底层实现重构。
- 通用 Prompt 管理平台。
- 多个同类型系统节点的负载均衡。
- 允许普通 AI 直接创建、修改或删除系统节点。

## Neuron Data Contract / 神经元数据契约

每个神经元至少包含：

- `id`：稳定神经元 ID。
- `desc`：简短描述。
- `content`：详细内容；系统提示词神经元以此承载提示词。
- `weight`：可正可负的权重。
- `system_type`：可空的系统用途标记。
- `tool_ids`：该神经元允许使用的系统工具 ID 集合。
- `created_at`、`updated_at`：创建和更新时间。

`system_type` 约束：

- 普通神经元的 `system_type` 为空。
- 非空 `system_type` 在全局范围内唯一。
- `system_type` 创建后不可通过普通 AI 更新工具修改。
- `system_type=create_neuron` 保留给神经元工具内部的创建系统节点。
- 课题匹配等 Hook 可以定义其他稳定 `system_type`，通过类型查找对应提示词节点。

`tool_ids` 约束：

- 保存稳定工具 ID，不复制工具定义。
- 空集合表示该神经元没有工具权限。
- 工具 ID 的解析和执行仍由系统工具注册表负责。
- 普通内容更新不得隐式改变 `tool_ids`。

## Update And Weight / 更新与权重

### 普通更新

- `update_neuron` 只允许更新 `desc` 和 `content`。
- `update_neuron` 不接受 `weight`、`system_type` 或 `tool_ids`。
- 普通 AI 调用 `update_neuron` 时只能更新普通神经元，不得改写任何非空 `system_type` 的系统节点。
- 未提供 `desc`、`content` 时不得产生无意义的数据变化。

### 权重增减

- 提供独立权重调整能力，入参至少包含神经元 ID 和 `delta`。
- `delta > 0` 增加权重，`delta < 0` 降低权重。
- 调整结果基于当前权重计算，不使用“读取后由调用方覆盖绝对值”的方式。
- 权重调整用于用户反馈、Hook 评分和人工管理；普通 AI 对话不直接获得任意调整权重的权限。
- **创建时强制零权重（2026-08-01 Reverse Sync）**：新建节点 `weight` 与新建边 `weight` 一律为 `0`；忽略模型 JSON / 调用方入参中的创建权重。初始差异只允许通过后续评价 delta 产生。详见 `docs/sdd-lab/2026-08-01_00-31_neuron-create-weight-zero/`。

## Create Downstream / 创建下游神经元

- 接收现有 `source_id` 和新神经元创建信息。
- 创建新神经元后建立 `source_id → new_neuron_id` 的有向边。
- 返回新神经元及连接结果。
- 该行为是一个完整业务动作；创建或连边失败时不得留下调用方误认为成功的半完成结果。
- 通过此能力创建的普通下游神经元默认 `system_type` 为空。
- 由自举流程调用时，新神经元内容来自模型生成结果。
- 创建落库时节点权重与边权重均为 `0`；AI 工具不得接受创建时 `weight` / `edge_weight` 参数。

## Model Dependency / 模型能力注入

- 神经元管理能力初始化时必须传入 `call_model`。
- `call_model` 是可调用依赖，接收模型请求并返回模型结果；神经元模块不直接依赖具体 Provider 实现。
- 该模型能力只供神经元内部的系统节点创建、普通神经元创建和候选补齐使用。
- 神经元内部调用模型时使用应用当前有效的模型选择；无可用模型时返回明确错误，不静默创建空神经元。
- `call_model` 不作为神经元 AI 工具暴露。

## Bootstrap / 自举创建

### 创建系统节点

- 内部首次需要创建神经元时，先查找 `system_type=create_neuron` 的系统节点。
- 如果不存在，使用内部私有创建能力建立一个该类型节点。
- 创建该系统节点所需的提示词规则必须可从应用配置读取。
- 配置缺失或无效时返回明确错误，不使用不可审计的临时提示词。
- 该内部私有创建能力不注册为 AI 工具。

### 缓存与恢复

- 找到或创建 `system_type=create_neuron` 节点后，神经元管理实例记录其 ID。
- 后续实例生命周期内优先使用已记录 ID，不需要每次重新按类型查询。
- 使用缓存前必须能够识别节点已删除、类型不匹配等失效情况。
- 缓存失效时重新查询；仍不存在则按配置重新创建并更新缓存。

### 使用系统节点创建其他神经元

- 定义内部能力：读取 `system_type=create_neuron` 节点内容，将其作为创建规则调用 `call_model`，再把结果持久化为普通神经元。
- 创建结果必须满足神经元必填字段要求，模型结果无效时不得写入残缺节点。
- 传入 `source_id` 时，创建结果必须通过“创建下游神经元”能力连接为其直接下游。
- 未传 `source_id` 时，创建结果作为全域普通神经元，不自动建立来源边。
- 所有由提示词驱动的神经元创建都必须先取得 `system_type=create_neuron` 节点，不允许绕过该系统节点临时拼装创建提示词。
- 自举候选入口以该系统节点 ID 作为 `source_id`，保证其直接下游最终有 7 个候选神经元供模型选择；已有节点不足时按候选补齐规则创建。

## Candidate Selection / 候选选择与自动补齐

统一候选能力接收：

- `n`：最终需要返回的神经元数量。
- `source_id`：可选来源神经元 ID。
- `system_type`：可选系统节点类型，用于找到唯一系统节点并以其 ID 作为候选来源。
- `min_new`：本轮至少创建的新神经元数量，范围为 `0..=n`。

选择规则：

- `source_id` 与 `system_type` 原则上只传一个；若同时传入，以 `source_id` 为准并忽略 `system_type`。
- 传入 `source_id` 时，只从其直接 `source → target` 下游集合选择，不递归遍历更深后代，也不使用全域节点补位。
- 未传 `source_id`、但传入 `system_type` 时，先找到该类型唯一系统节点，再从该节点的直接下游集合选择。
- `system_type` 对应节点不存在时返回明确错误；除 `system_type=create_neuron` 的既定自举规则外，不自动创建其他类型的系统节点。
- `source_id` 与 `system_type` 均未传入时，从全域普通候选神经元中选择。
- 候选按高权重优先。
- 同权重候选随机抽取，不依赖固定存储顺序。
- 本轮至少新建 `min_new` 个神经元。
- 选择与最低创建数处理后总数仍不足 `n` 时，继续通过自举创建补齐到 `n`。
- 通过 `source_id` 或 `system_type` 确定来源节点时，所有自动补齐节点都必须成为该来源节点的直接下游；无来源时创建为全域普通节点。
- 返回结果不得包含重复神经元，且数量必须为 `n`；无法补齐时整体返回明确错误。

例如：`n=7`、`min_new=2` 时，本轮至少新建 2 个；其余优先从目标集合选择。如果可用旧节点不足 5 个，则继续创建，直到最终得到 7 个。

## Capability Exposure / 能力暴露边界

### AI 工具

适合向普通 AI 暴露：

- 获取单个神经元及其连接。
- 列出神经元。
- 查看神经元网络。
- 更新神经元 `desc` 和 `content`。
- 创建并关联下游神经元，但必须经过受控创建流程，不能指定 `system_type`。
- 按 `n`、可选 `source_id`/`system_type`、`min_new` 选择并自动补齐候选。

### 内部私有能力

不得注册为普通 AI 工具：

- 原始神经元创建。
- 注入和调用 `call_model`。
- 查找、创建、缓存和恢复 `system_type=create_neuron` 节点。
- 使用创建系统节点生成其他神经元。
- 根据用户反馈或 Hook 结果增减权重。
- 直接设置或迁移 `system_type`、`tool_ids`。

### 人类管理入口

适合通过 TUI、CLI 或其他明确的管理入口提供：

- 查看全部神经元及系统节点。
- 修改普通神经元内容。
- 调整权重。
- 删除普通神经元及其关联边。
- 通用 link/unlink。
- 配置或修复 `system_type`、`tool_ids`。
- 查看和修复创建系统节点。
- 按 `n`、可选 `source_id`/`system_type`、`min_new` 手动触发候选选择和自动补齐。
- 手动触发自举诊断。

人类管理入口可以复用底层业务能力，但不应为了复用而把高权限管理动作注册成普通 AI 工具。

## Constraints / 约束

- 需求阶段只确认业务边界；技术方案单独落盘，未获执行批准前不修改代码。
- 无新增外部依赖。
- 系统节点和普通节点共用神经元存储，但权限与可修改字段必须区分。
- 系统节点的普通 AI 写入权限默认关闭。
- 候选选择不得依赖 SQLite 未声明的返回顺序。
- 具体 Rust 类型签名、数据库迁移方式、事务实现和配置键名在技术方案阶段确定。

## Open Questions / 开放问题

当前无阻塞需求问题。以下决策已确认：

- `system_type` 可空、同类型全局唯一，且创建后不可通过普通 AI 工具修改。
- 有 `source_id` 时使用其直接下游；仅有 `system_type` 时使用对应系统节点的直接下游；两者均无时使用全域集合。
- 候选使用 `min_new` 语义，并在总数不足时继续自动补齐到 `n`。
- 候选来源也可以通过 `system_type` 定位；`source_id` 与 `system_type` 同时出现时以 `source_id` 优先。
