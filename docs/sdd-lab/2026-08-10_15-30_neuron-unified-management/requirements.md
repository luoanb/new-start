# Requirements / 需求文档: Neuron Unified Management

## Restated Understanding / 需求复述

- 我理解当前需求是：把「系统神经元」与「普通神经元」收拢到统一的神经元管理入口与统一编辑流程中。两者同属神经元（一个数据源），只是筛选与展示方式不同；系统神经元的行为管理（selection / tools / insert_id）纳入统一编辑区。
- 当前核心目标是：右侧 info 栏新增《神经元》列表 panel 作为管理入口；主区域《神经元》面板降级为画布子页面（数据源改为列表选中项）；节点编辑弹窗扩展系统类型绑定与行为管理控件。
- 当前边界是：仅管理「数据」——列表/筛选/选中/编辑（含系统类型与行为）；系统神经元的外部解释与使用（如会话如何消费）不属于本迭代。
- 暂不处理：系统神经元的会话语义、行为如何被执行、`assistant_*` 裁决类的使用流程。

## Scope / 范围

- In:
  - 右侧 info 容器《模型》视图右侧新增《神经元》列表 panel（管理入口）。
  - 列表能力：常规列表展示全部神经元；搜索；类型筛选；滚动到底部「加载更多」（分页/增量加载）。
  - 列表选择：点击项设为画布核心（单选）；顶栏多选开关，打开后允许多选。
  - 列表项「编辑」按钮：打开节点编辑弹窗。
  - 主区域《神经元》面板降级：移除搜索与核心筛选框（数据源 = 列表选中项）；保留深度 / 布局 / 连线方式 / 节点工具栏「设为画布核心」；创建（孤立）入口移至列表面板。
  - 节点编辑弹窗：保留原始功能（desc / content / tool_ids / 权重等）。
  - 系统类型管理：查看；非系统神经元可自行绑定；已绑定者换绑 / 取消绑定需二次确认；绑定后新增行为管理控件（selection / tools / insert_id）。
  - 裁决类（`assistant_*`）行为开放管理面编辑（后端 `update_behavior_for_admin` 放行范围由 `session.*` 扩展）。
- Out:
  - 系统神经元的解释 / 使用语义（如何被会话消费、hooks 编排）。
  - 行为（behavior）执行的运行时行为变更。
  - 画布可视化算法、布局算法本身的改动（仅保留现有能力）。
  - 多系统神经元会话切换、会话中途更换系统神经元。

## User Interaction / 用户交互

- 触发入口：
  - 右侧 info 容器《神经元》列表 panel（《模型》视图右侧新增 tab）。
  - 列表项「编辑」按钮 → 节点编辑弹窗。
- 用户操作路径：
  - 进入：打开《神经元》列表 panel → 展示神经元常规列表（默认单选模式）。
  - 筛选：搜索框输入 / 类型筛选下拉 → 列表实时过滤。
  - 分页：滚动到列表底部显示「加载更多」项，点击加载下一批。
  - 单选：点击列表项 → 该项高亮为选中 → 主区域画布以该项为核心展开（subgraph 刷新）。
  - 多选：打开顶栏多选开关 → 列表项变勾选框，勾选多项 → 画布以多项为核心展开。
  - 编辑：点列表项「编辑」→ 打开节点编辑弹窗（desc / content / tool_ids / 权重 / 系统类型 / 行为）。
  - 绑定系统类型：非系统神经元 → 编辑弹窗内输入/选择 system_type → 保存后编辑区出现行为管理控件。
  - 换绑 / 取消绑定：已绑定系统类型 → 修改或清空 → 二次确认弹窗 → 确认后保存。
  - 创建：列表主面板「创建神经元（孤立）」→ 创建弹窗（原有流程）。
  - 画布设核心：画布节点工具栏「设为画布核心」→ 同步回列表选中项。
- 系统反馈：
  - 列表项选中高亮；画布 subgraph 随核心变化刷新。
  - 编辑保存成功/失败提示；系统类型绑定成功/失败提示（如 system_type 唯一冲突）。
  - 二次确认弹窗明确展示「将换绑为 X」/「将取消绑定系统类型」的后果。
- 状态变化：
  - 列表选中项（单选/多选）→ 驱动画布核心。
  - 神经元 `system_type` / `behavior` 变更落库并触发列表与画布刷新。
- 异常/边界交互：
  - 列表无选中项 → 画布显示空态（保持现有 empty 提示）。
  - 绑定的 system_type 已存在 → 提示冲突（唯一索引约束），不落库。
  - 多选模式下画布核心超出可视范围/深度限制 → 按现有 pruneByDepth 规则收敛。
- 不应发生的交互：
  - 未确认的换绑 / 取消绑定直接落库。
  - 普通神经元（无系统类型）出现行为管理控件。
  - 画布内直接编辑系统类型而绕过编辑弹窗的二次确认。

## Acceptance Criteria / 验收标准

- [ ] info 容器《模型》视图右侧新增《神经元》列表 panel，作为神经元管理唯一入口（`session-specs` 独立面板移除或入口收敛）。
- [ ] 列表支持：常规展示全部神经元（含系统/普通标识）、搜索、类型筛选、滚动到底部「加载更多」。
- [ ] 单选：点击列表项设为画布核心；多选开关打开后支持勾选多项，画布以多项为核心。
- [ ] 主区域《神经元》面板：搜索与核心筛选框移除；深度 / 布局 / 连线方式 / 「设为画布核心」保留；创建（孤立）入口移至列表主面板。
- [ ] 节点编辑弹窗：原始功能保留；非系统神经元可绑定系统类型；已绑定者换绑 / 取消绑定有二次确认。
- [ ] 绑定系统类型后，编辑区出现行为管理控件（selection / tools / insert_id）并可保存生效。
- [ ] 裁决类（`assistant_*`）行为可在管理面编辑（后端放行）。
- [ ] `cargo check` / `cargo test --lib` 通过；`svelte-check` 无错误；既有行为不回退。

## Constraints / 约束

- 业务约束：
  - 系统神经元与普通神经元同表（`neurons`），`system_type` 非空即系统神经元；唯一索引约束 system_type。
  - 行为（`SessionBehavior`）承载于 `neurons.behavior` 列，仅系统神经元可挂载。
  - 「只管理数据」：行为管理控件只负责编辑与保存数据，不涉及外部如何解释/使用。
- 技术约束：
  - 复用现有组件与机制：`BehaviorFields` 表单（SessionSpecsPanel 内 snippet）、`NeuronDetailDrawer` / 编辑弹窗、`layoutStore.insertPanel`、info 容器视图注册（`viewRegistry`）。
  - 前端列表懒加载需后端配合：`list_neurons` 当前一次性返回全量，需评估分页接口或前端增量加载。
  - `update_behavior_for_admin` 放行范围需扩展（`session.*` → 全部系统神经元），并保持 `update_content_for_admin` 双写不冲突。
- 时间/兼容性约束：
  - `pulsar:layout` 本地布局持久化（version 8）：新增视图/面板需兼容旧布局迁移。
  - 移动端（drawer 模式）需适配新增列表入口。
