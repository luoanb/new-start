# Requirements / 需求文档: agent-app-gui-redesign

## Restated Understanding / 需求复述

- 我理解当前需求是：基于 `packages/agent-app` 的 Svelte 前端，参考 TUI (`src-tauri/src/tui/`) 已支持的交互能力以及 Rust Core (`src-tauri/src/core/`) 已暴露的接口，重新设计并完善 GUI 界面，使其成为一个功能完整、体验流畅的 AI Agent 桌面客户端。
- 当前核心目标是：GUI 的功能覆盖度追上 TUI，并在 Web 原生交互（表单、列表、弹窗、视觉层级）上超越终端体验。
- 当前边界是：本轮先产出需求文档，不进入代码实现；设计应基于现有的 Tauri 命令和 Rust Core 接口，不触发 Rust 后端变更。
- 暂不处理：token streaming（与 TUI 一致，另开迭代），会话 compaction 的 UI（非高频操作），Neuron 管理界面（图结构 UI 复杂度高），Svelte 5 迁移或版本升级，端到端 E2E 测试框架。

## Scope / 范围

### In

1. **Chat 工作台（主功能）**
   - 全会话聊天消息流展示（区分 user / assistant / system / tool / error 角色）
   - 消息输入框（支持多行、Enter 发送）
   - 输入历史导航：↑/↓ 键循环召回已发送消息，方便重复或修改发送
   - 发送消息后自动滚动至最新消息
   - 当前会话历史加载与展示
   - 消息内容展示（纯文本，不做 markdown 渲染或代码高亮，与 TUI 一致）

2. **会话管理**
   - 会话列表侧栏或面板，展示所有会话（ID、消息数、更新时间、会话模式标签）
   - 会话模式标签清晰区分三种模式：
     - **Chat**：普通对话，一问一答，不调用工具，无自主推进
     - **Agent**：可调用工具的对话，Engine 会按需执行 tool-calling 循环
     - **Assistant**：自主推进模式，Poller 按 tick 调度，Neuron 驱动话题深入
   - 点击切换当前会话，自动加载历史消息
   - 新建会话时弹出模式选择（Chat / Agent / Assistant），附带简要模式说明
   - 会话创建后模式不可变更（Rust 端 Conversation 的 mode 字段创建即固定）
   - 当前活跃会话的模式在顶部状态栏同步展示
   - 清空当前会话
   - 关闭运行中会话（Assistant 模式下运行的会话，可主动停止）
   - 会话列表中标记当前活动会话

3. **模型与服务商管理**
   - 服务商列表展示（ID、display_name、auth_env、api_base、kind）
   - 模型列表展示（ID、provider_id、capabilities、context_window、pricing）
   - 按服务商筛选模型
   - 选择当前对话使用的 provider / model 组合
   - 展示当前选中的活跃模型

4. **系统状态与信息展示**
   - 运行时状态（当前会话、存储路径、技能数、会话数）
   - 技能列表（name + description）
   - 配置信息展示（storage path、当前会话、活跃模型）

5. **导航与布局**
   - 顶部状态栏/导航区（应用名称、当前会话、会话模式标签、活跃模型）
   - 主内容区（聊天流或功能面板）
   - 侧栏（会话列表、服务商/模型/技能信息分页）
   - 响应式基础布局（窗口缩放合理适配）

6. **错误处理**
   - 错误信息以醒目方式展示（非 console / alert）
   - 结构化错误提示（错误消息 + 可能原因或修复建议，参考 TUI `error_view.rs` 风格）

### Out

- Token streaming：与 TUI 一致，不纳入第一版 GUI 改造
- 主题自定义或主题切换器：使用系统深色/浅色模式（已有 CSS 支持）
- 会话 compaction 的 UI 操作（低频管理功能，可通过 CLI/TUI 完成）
- Markdown 渲染或富文本消息展示
- 工具调用/Task 块的状态折叠展示（TUI 特有概念，GUI 以更自然的异步 loading 展示）
- Neuron 管理界面：涉及图结构遍历、权重调整、连接管理，UI 复杂度高，保留 CLI/TUI 入口
- Topic / Poller 管理界面：数据管理功能，GUI 第一版聚焦聊天核心体验，Topic/Poller 可后续迭代
- 无会话模型直接调用面板：移除现有独立面板，模型调用统一通过会话内聊天工作台完成

## User Interaction / 用户交互

- **触发入口**：用户运行 `pnpm tauri dev` 或构建后的桌面应用启动。
- **用户操作路径**：
  1. 启动后直接进入聊天工作台，左侧显示会话列表（含模式标签），主区显示当前会话消息流。
  2. 底部输入框输入消息 → Enter 发送 → 消息出现在聊天流 → 模型响应追加。
  3. 点击会话列表中的其他会话 → 切换加载该会话历史。
  4. 使用 "+" 或 "新建会话" 按钮 → 弹出模式选择弹窗（Chat / Agent / Assistant），附带简要说明，选后自动创建并进入。
  5. 导航栏或侧栏切换查看服务商列表、模型列表、技能列表、运行时状态。
  6. 顶部下拉选择当前对话使用的 provider / model。
  7. 键盘操作：Tab 切换焦点区域，↑/↓ 在输入框中回溯历史，↑/↓/PgUp/PgDn 滚动聊天区，Ctrl+J 快速新建会话（默认 Chat 模式）。
- **系统反馈**：
  - 消息发送后立即显示在聊天流，模型响应异步追加。
  - 加载中显示 loading 状态（输入框禁用 + 发送按钮禁用 + 加载指示器）。
  - 切换会话时显示加载过渡（消息列表替换、滚动复位）。
  - 错误以醒目 banner 或 inline toast 展示。
- **状态变化**：
  - 当前会话切换 → 聊天流重置为该会话历史，顶部活跃模型和模式标签同步更新。
  - 新建会话 → 弹出模式选择，选择后跳转至对应模式的空会话，默认使用当前活跃模型。
  - 模型切换 → 仅影响后续消息发送，不影响历史消息。
  - 会话模式不可变更（创建即固定），模式标签仅用于展示和区分。
  - 无活跃模型时发送消息 → 展示错误提示 + 引导选择模型。
- **异常/边界交互**：
  - provider/model 未选择时发送 → 展示错误提示，不发起请求。
  - API key 缺失或请求失败 → 展示错误消息，不崩溃。
  - 会话列表为空 → 展示"暂无会话，创建一个"的空状态 + 操作引导。
  - 网络超时 → 展示超时错误，允许重试。
  - 窗口尺寸过小 → 侧栏自动折叠或隐藏。
- **不应发生的交互**：
  - 错误直接弹出原生 `alert()` 或写入 console 不可见。
  - 发送消息后界面无任何反馈（loading 或错误）。
  - 切换会话导致已发送但未收到回复的消息丢失。
  - 初次使用无活跃模型时发送消息静默失败。

## Constraints / 约束

- 业务约束：
  - 文档和代码冲突时，以文档为准，先同步文档再同步代码。
  - 没有用户明确确认技术方案前，不进入代码开发。
  - `Spec is Truth`，`No Spec, No Code`，`No Approval, No Execute`。
- 技术约束：
  - 新增 Tauri 命令仅限于对 Gateway 现有方法的封装，不做后端新业务逻辑。
  - GUI 不应绕过 Tauri 命令直接访问 Rust 后端 state / storage。
  - 前端技术栈保持 SvelteKit + Svelte 5 + `@tauri-apps/api`。
  - UI 层面使用原生 Web 技术（CSS Grid/Flexbox），不引入额外 UI 组件库。
- 时间/兼容性约束：
  - 第一版以桌面窗口为目标，不做移动端适配。
  - 键盘快捷键优先，明确以下键位映射：
    - Enter：发送消息
    - Shift+Enter：输入框内换行
    - ↑/↓：输入历史导航（输入框焦点时）
    - ↑/↓ / PageUp / PageDown：聊天区手动滚动（聊天区焦点时）
    - Tab：焦点在输入框 ↔ 聊天区 ↔ 侧栏之间切换
    - Ctrl+J：快速新建会话（与 TUI 保持一致）
    - Esc：关闭弹出/覆盖层、取消编辑或取消选中
    - Ctrl+C：仅复制选中文本，不退应用（桌面原生行为）
