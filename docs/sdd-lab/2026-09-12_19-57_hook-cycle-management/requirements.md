# Requirements / 需求文档: Hook 周期管理（流程决策升级）

## Restated Understanding / 需求复述

- 我理解当前需求是：把现有「流程决策」面板从「裁决账本只读时间线」升级为「**周期管理**」——把系统内各种「**按条件、按节奏执行的调度动作**」集中呈现出来，并允许按需调整。
- 业务侧要的是**效果**（例如「简报刷新节奏要能控」「选型不必每轮都调模型」）；至于**配成什么值、怎么配才能达到该效果，取决于提供方给出了哪些参数**——提供方没给的参数，就配不出对应的效果。
- 当前核心目标是：
  1. **事前可见**：能看到系统里有哪些调度动作、挂在哪个环节、当前是否启用、当前节奏是多少；
  2. **可调**：在提供方给出的参数范围内取值，把效果配到业务期望；
  3. **可启停**：全部动作统一可启停；对「关停会破坏业务语义」的动作给**风险提示**（不硬拦截）；
  4. **持久化 + 即时生效**：配置写盘、重启保留、改动立刻生效；
  5. **保留执行记录**：现有账本时间线作为运行观测不回归。
- 当前边界是：
  - 只升级现有 `hook-judgements` 视图（视图 id 保留，改展示名与文案）；
  - **业务侧要保留的功能效果一条不少**（见 §业务诉求清单）；
  - 不改注入点契约、不改 runner 核心五步、不改账本表结构。
- 暂不处理：
  - 休眠 4 条裁决（`score_feedback` / `match_topic` / `revise_topic` / `complete_scope`）维持「定义·未注册」，本轮不纳入启停/配置；
  - per-topic / per-session 级配置；
  - 视觉稿（本轮无 Figma）。

## Business Requirements / 业务诉求清单（核心）

> 这些是**功能效果**（业务侧要保留的东西）；「今天的效果值」是当前代码里的效果，默认值应保持不变。
> 「可调诉求」= 是否需要开放给消费方调整（**全部动作均可调**，各按其可调项声明）。

| # | 调度动作 | 归属位置 | 要达到的效果 | 今天的效果值 | 可调诉求 |
|---|---|---|---|---|---|
| 1 | 用户轮裁决 | 轮前（IP-1）`assistant.user-round-judgement` | 助手模式下按用户轮次节奏触发课题裁决；**未绑定课题必须触发**（保证会话能建立课题）；已绑定课题时低频复核（省模型调用） | 仅助手/系统模式；仅用户轮；未绑定每次都跑，已绑定每 **3** 条用户消息一次 | 是（节奏 N） |
| 2 | 轮次复盘 | 轮后（IP-5）`assistant.round-review` | **仅「模型说完了」的收尾轮**做复盘；工具轮的中间产物不复盘 | 仅助手/系统模式；仅收尾轮 | 是（是否仅收尾轮） |
| 3 | 轮前准备 | 轮前（IP-1）`assistant.round.before` | 助手模式下每轮做课题解析与推进；用户接入时解除「等待用户」 | 仅助手/系统模式 | 是（模式窗口） |
| 4 | **简报刷新**（发生在轮前准备内部） | 轮前准备内部（非独立动作） | 喂给模型的课题简报要「新鲜但不啰嗦」：**隔一定轮次必须刷新**；课题内容有变化时立即刷新；上轮不是工具结束时也刷新 | 每 **3** 个推进轮（或内容变化 / 上轮非工具结束） | 是（轮次 N + 「上轮非工具结束」开关；「内容变化」属业务态，留内部不可配） |
| 5 | **选型**（节流） | 轮前（IP-1）`assistant.select-neuron` | 神经元选型要**节流**：不必每轮都调模型选型，隔几轮选一次，其余轮沿用上次结果 | 每 **5** 个推进轮做一次 | 是（轮次 N） |
| 6 | 轮次计数 | 轮后（IP-5）`assistant.round.after` | 每轮成功结束后更新轮次计数与「末轮待续推」标记（供轮询判断是否继续） | 仅助手/系统模式 | 是（模式窗口） |
| 7 | 压缩 | 落库后·调用前（IP-2）`core.compaction` | 上下文接近模型窗口上限时自动压缩，避免请求超限失败 | 超过上下文窗口的 **50%** 时压缩 | **不属周期**：动作每轮都调用，是否压由内部按阈值检测 |

- **第 4、5 项必须明确**：它们发生在「轮前准备」这个动作**内部**，不是独立动作；但业务侧要求它们**同样可调**，不能因为「在内部」就丢出范围。

## Cycle Fields / 周期字段集（框架派生）

> **抽象原则**：周期条件只能建立在**框架能从 `RoundContext` 派生出来的字段**上。
> 业务状态（课题是否绑定 / 课题状态 / 神经元 / 记忆等）**不进周期条件**——由 hook 内部按当前上下文（如 `ctx.session_id`）自行查询判断。

### 可用字段

| 字段 | 类型 | 派生式 | 备注 |
|---|---|---|---|
| `mode` | 枚举 | `ctx.mode` 直取 | 会话模式 |
| `trigger` | 枚举 | `ctx.trigger` 直取 | 本轮触发来源 |
| 轮次计数（本对话第几轮） | 数值 | `messages` 中 `role == Assistant` 的条数 | 与现有计数**并存**，不替换 |
| 用户介入轮次计数 | 数值 | `messages` 中 `role == User` 的条数 | 同上 |
| 距上次用户介入的推进轮次 | 数值 | 最后一条 `role == User` 之后的 `role == Assistant` 条数 | 同上（= 工具轮 + 调度轮累计） |
| **轮次来源**（正交维度 A） | 枚举 | `trigger == User` ? 用户轮 : 调度轮 | 调度轮 = 非用户触发 |
| **产物形态**（正交维度 B，**可指定轮次**） | 枚举 | 指定轮次有 `tool_calls` / `tool_results` ? 工具轮 : 收尾轮 | 轮次可取 **本轮** 或 **上一轮**；与维度 A 组合成四象限 |
| 注入点 | —（静态已知） | hook 的挂载点本身 | 不作字段，不言自明 |

- 「用户轮 / 工具轮 / 调度轮 / 收尾轮」**不是单一互斥枚举**，而是两个正交维度：`(用户轮｜调度轮) × (工具轮｜收尾轮)`。
- **产物形态支持指定轮次**：
  - **本轮** —— 仅 IP-3 及之后可用（产物才产生）；
  - **上一轮** —— **任意注入点可用**，派生式 = `messages` 末条是否 `role == Tool`（即现行 `last_message_is_tool_result` 的判据）；
  - 用途：IP-1 / IP-2 场景需要「上一轮是否以工具结束」（如简报刷新的「上轮非工具结束时刷新」）。

### 派生口径约束

| 注入点 | 本轮用户消息 | 本轮产物 | 派生口径 |
|---|---|---|---|
| IP-1 / IP-2 | 未落库 / 已落库 | 尚未产生 | **不含本轮**（= 上一轮为止） |
| IP-3 / IP-4 / IP-5 | 已落库 | 已产生（IP-5 于 `ctx.outcome`） | **含本轮** |

- 因此**「本轮产物形态」条件在 IP-1、IP-2 不可用**；此时要判产物形态只能用「上一轮」（任意注入点可用）。
- 现有 `need_user_round_judgement` 依赖 IP-1 的「不含本轮」语义（`0 % N == 0` 恰好覆盖首轮）；派生实现必须保持该偏移，否则首轮会漏跑。
- **计数并存**：新增派生值仅用于周期条件；现有 `topic.extra` 计数（`total_rounds` / `user_rounds` / `poll_count`，被轮询退避 / 暂停等既有逻辑消费）保持不动。

### 边界示例

- ✅ 周期条件可写：「仅用户轮」「每 N 轮」「仅收尾轮」（本轮限 IP-3 及之后；上一轮任意注入点）
- ❌ 周期条件不可写：「仅在已绑定课题时」（业务状态）→ 由 hook 内部判断保留
- ❌ 不属周期：「是否压缩」——压缩动作**每轮都会被调用**，是否压由 hook 内部按阈值检测决定，与周期无关
- 例：用户轮裁决的「未绑定课题必跑」属业务状态判断，**不进周期条件**；周期只表达「用户轮 + 每 N 次」。

## Scope / 范围

- In:
  - **业务诉求落地**：§业务诉求清单 中「可调」的效果全部保留且可调，默认值不变；
  - **调度动作清单（事前可见）**：列出动作名称、所属环节、当前启用状态、当前节奏值；
  - **调整（按提供方给的参数取值）**：消费方只能在提供方给出的参数范围内取值，配出业务期望的效果；
  - **启停**：全部动作统一可启停，改动即时生效；关停会破坏业务语义的动作给**风险提示**（不硬拦截）；
  - **持久化**：全局 `config.json`，重启保留；
  - **执行记录区保留**：现有账本时间线（过滤 / 滚动分页 / 详情 / 定位）不回归；
  - **展示名**：面板标题「流程决策」→「周期管理」（en "Cycle Management"）。
- Out:
  - 休眠 4 条裁决的注册化 / 可见化 / 启用化；
  - **正确性不变量**纳入可配（见 §Constraints）；
  - 注入点契约、runner 核心五步、账本表结构变更；
  - 新增注入点、新增 hook 实例、裁决语义变更；
  - per-topic 配置与多套配置档；
  - 表达式字符串 / 脚本引擎作为配置手段。

## User Interaction / 用户交互

- 触发入口：sidebar「周期管理」视图（原「流程决策」，视图 id 仍为 `hook-judgements`）。
- 用户操作路径：
  - 打开面板 → 看到调度动作清单（名称 / 环节 / 启用状态 / 当前节奏）→ 点开某条 → 在提供方给出的参数上取值 → 保存 → 切到「执行记录」区查看该动作的运行记录。
  - 「执行记录」区切换过滤下拉即时重查（重置到第一页）。
- 系统反馈：
  - 保存成功 → 面板状态即时更新 + 短暂成功提示；
  - 保存失败（值超出范围 / 形态不合法）→ 就地错误提示，值回滚到保存前。
- 状态变化：
  - 启用状态变化、生效参数值变化；两者均持久化，重启后保留。
- 异常/边界交互：
  - 关停高风险动作（会破坏业务语义）时：给出风险提示，不拦截；
  - 关闭某动作后，其运行记录不再新增（既有记录仍可查）；
  - 清单为空（异常）→ 空态提示；
  - 配置读取/解析失败 → 回落默认并提示，不阻断启动。
- 不应发生的交互：
  - 面板展示的状态与实际运行行为不一致；
  - 关闭后仍执行（或开启后不生效）；
  - 保存后未持久化，重启丢失。

## Acceptance Criteria / 验收标准

- [ ] 面板能列出全部调度动作及其**当前启用状态**与**当前节奏值**。
- [ ] 业务侧效果可调且默认值不变：
  - [ ] 用户轮裁决节奏可调（已绑定课题时每 N 条用户消息；未绑定必须触发不变）
  - [ ] 轮次复盘可调（是否仅收尾轮）
  - [ ] **简报刷新可调**（轮次 N + 「上轮非工具结束时刷新」开关；「内容变化时刷新」属业务态，不可配）
  - [ ] **选型节奏可调**（每 N 个推进轮）
  - [ ] 轮前准备 / 轮次计数可调（模式窗口）
- [ ] 调整后的行为符合新值（如把简报 N 改为 10，则确实每 10 个推进轮才刷新一次）。
- [ ] 全部动作可统一启停，切换后立即生效并重启保留；关停高风险动作时给出风险提示。
- [ ] 非法取值（如 N 超出范围）被拒绝且不落盘。
- [ ] 业务侧效果**无回归**：不调整时，助手模式的裁决 / 复盘 / 简报 / 选型行为与今天一致。
- [ ] **通用性**：新增一处调度动作时，界面上自动出现该动作及其参数（不需要为该动作单独开发界面）。
- [ ] 账本时间线区不回归（过滤 / 滚动分页 / 详情展开 / 在会话中定位）。
- [ ] 展示名：zh「周期管理」/ en "Cycle Management"；视图 id `hook-judgements` 保留。
- [ ] 测试与静态检查通过：`cargo test --lib` 全绿；`pnpm --filter pulsar-app check` 0 error。

## Constraints / 约束

- 业务约束（**正确性不变量，不允许被配置破坏**）：
  - 暂停 / 等待用户状态的课题不写复盘；
  - 空待办清单 → 课题置为完成（防止轮询空转）；
  - `WrappingUp` 课题在文本收尾后关闭；
  - `completed` 勾选仅用户轮放行；
  - 未绑定课题时兜底建立并绑定课题（保「会话必须绑定课题」）；
  - 裁决失败不阻断主轮（中性降级保持）；
  - 轮次计数本体（推进轮次 / 总轮次 / 用户轮次）与注册顺序。
- 抽象约束（**周期模型边界**）：
  - 周期条件**只能引用框架从 `RoundContext` 派生的字段**（见 §周期字段集）；**业务状态不进周期条件**，由 hook 内部自行判断；
  - 周期 = **调度**（何时调用动作）；动作被调用后「内部怎么决策」属业务（如压缩每轮调用、内部按阈值决定是否压；简报刷新的「内容变化」判定）；
  - 计数采用**并存**策略：新增派生值仅服务周期条件，现有 `topic.extra` 计数与依赖它的既有逻辑不动。
- 技术约束：
  - 本轮**暂无**（技术方案撤销后待重做）；底线是不引入新外部依赖。
- 时间/兼容性约束：
  - 视图 id `hook-judgements` 不变（布局持久化安全）；
  - `hook_judgements_list` 出参与账本表结构不变，存量记录照常展示；
  - `config.json` 未建模键不丢数据。
