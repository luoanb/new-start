# Requirements / 需求文档: agent-app-theme-markdown-toolcall

## Restated Understanding / 需求复述

- 我理解当前需求是：在 agent-app GUI 第一版（已覆盖聊天工作台、会话管理、模型管理、系统状态展示）的基础上，增加三个增强功能：主题切换器（用户手动选择 light / dark / system）、消息 Markdown 渲染与富文本展示、工具调用块的折叠展示。
- 当前核心目标是：提升 GUI 的消息阅读体验和视觉控制能力，使其在信息展示丰富度上超越 TUI。
- 当前边界是：设计应基于现有的 Tauri 命令和 Rust Core 接口及 Message 数据结构，不触发 Rust 后端变更；仅涉及前端渲染和交互增强。
- 暂不处理：主题编辑器（自定义色值）、代码高亮主题切换、消息编辑、消息搜索。

## Scope / 范围

### In

1. **主题切换器**
   - 支持三种模式：Light（浅色）、Dark（深色）、System（跟随系统）
   - 切换入口：顶部状态栏区域，下拉选择器或图标按钮
   - System 模式下监听 `prefers-color-scheme` 变化自动切换
   - 切换即时生效，不影响布局或组件状态
   - 用户选择的偏好持久化（localStorage 或 Tauri store）

2. **Markdown 渲染或富文本消息展示**
   - 在 ChatMessage 组件中，对 assistant / user 角色的消息内容进行 Markdown 渲染
   - 支持的 Markdown 元素：标题（h1-h6）、段落、列表（有序/无序）、代码块（含语言标签）、行内代码、粗体/斜体、链接、水平线、表格、引用块
   - 代码块渲染：使用纯 CSS 样式营造代码块外观，带语言标签标识；不引入代码高亮库
   - 纯文本消息（无 Markdown 语法）保持原样展示
   - system / tool / error 角色的消息保持纯文本（不做渲染）
   - 安全性：对渲染内容进行 XSS 防护（DOMPurify 或类似方案）

3. **工具调用折叠展示**
   - 消息中的工具调用（`Message.tool_calls`）以折叠块形式展示
   - 默认折叠状态，展开显示工具调用详情（工具名称、参数、执行结果）
   - 折叠块样式与普通消息气泡区分（侧边指示条或背景色差异）
   - 支持单条消息内多个工具调用的列表展示
   - 工具调用和文本内容在同一消息中自然衔接

### Out

- 代码语法高亮主题切换
- 消息 Markdown 源码编辑/切换
- 自定义主题色编辑器
- 消息搜索/全文检索
- Markdown 中的图片渲染
- 工具调用执行进度流式展示（实时更新）

## User Interaction / 用户交互

- **触发入口**：应用启动后，顶部状态栏可见主题切换图标/下拉。消息展示自动包含 Markdown 渲染和工具调用折叠。
- **用户操作路径**：
  1. 点击主题切换器 → 在下拉中选择 Light / Dark / System → 主题立即切换并持久化
  2. 浏览历史消息 → Markdown 内容自动渲染为富文本，代码块带语言标签和样式
  3. 消息中包含工具调用 → 默认显示为折叠块（如 "🛠 调用 get_current_time"），点击展开详情
  4. 展开的工具调用显示：工具名称、传入参数（JSON 格式化）、执行结果
- **系统反馈**：
  - 主题切换即时生效，无闪烁或过渡延迟
  - Markdown 渲染失败时回退为纯文本，不报错
  - 工具调用折叠展开/收起有平滑动画
- **状态变化**：
  - 主题切换器状态持久化，重启后恢复上次选择
  - 工具调用的折叠状态为组件级，不影响其他消息
- **异常/边界交互**：
  - 消息包含恶意 Markdown → XSS 过滤，仅渲染安全的 HTML 子集
  - 超大代码块 → 设置最大高度＋滚动，不撑破布局
  - 工具调用内容过长 → 展开区内限制高度＋滚动
  - Markdown 表格列数过多 → 水平滚动
- **不应发生的交互**：
  - 主题切换导致布局错位或组件闪烁
  - Markdown 渲染破坏消息流布局
  - 工具调用折叠块干扰正常消息阅读
  - 切换主题后深色/浅色模式的 CSS 变量未正确应用

## Acceptance Criteria / 验收标准

### 主题切换器
- [ ] 状态栏包含主题切换入口（下拉或按钮）
- [ ] Light / Dark / System 三种模式可正常切换
- [ ] System 模式下，跟随系统主题变化自动切换
- [ ] 主题偏好重启后保持
- [ ] 切换过程中无 UI 闪烁或布局偏移

### Markdown 渲染
- [ ] 标题（h1-h6）正确渲染为对应字号和粗体
- [ ] 有序/无序列表正确渲染（含嵌套）
- [ ] 代码块渲染为独立区块，带深色背景、等宽字体、语言标签
- [ ] 行内代码渲染为带浅底色和等宽字体的内联样式
- [ ] 链接可点击（在新窗口打开）
- [ ] 表格正确渲染，列过多时水平滚动
- [ ] 引用块渲染为左侧竖线标记的区块
- [ ] XSS 注入内容被过滤，不执行脚本

### 工具调用折叠展示
- [ ] 含 tool_calls 的消息显示为折叠块
- [ ] 折叠块默认收起，点击展开
- [ ] 展开后显示工具名称、参数（JSON 格式化）、执行结果
- [ ] 同消息内多个工具调用列表展示
- [ ] 折叠块样式与普通气泡明显区分

## Constraints / 约束

- 业务约束：
  - 文档和代码冲突时，以文档为准，先同步文档再同步代码。
  - `Spec is Truth`，`No Spec, No Code`，`No Approval, No Execute`。
- 技术约束：
  - 新增 Tauri 命令仅限于对 Gateway 现有方法的封装，不做后端新业务逻辑。
  - GUI 不应绕过 Tauri 命令直接访问 Rust 后端 state / storage。
  - 前端技术栈保持 SvelteKit + Svelte 5 + `@tauri-apps/api`，不引入额外 UI 组件库。
  - Markdown 渲染库选择：marked（解析） + DOMPurify（安全过滤），轻量无额外 UI 依赖。
  - 主题持久化使用 localStorage（Svelte 5 $state 同步），不新增 Tauri 插件。
  - 原 CSS 变量体系（`--color-bg`, `--color-surface` 等）作为主题基础，主题切换器通过切换 `data-theme` 属性控制变量生效组。
- 时间/兼容性约束：
  - 不引入 Tailwind 或其他 CSS 框架。
  - 代码块样式纯 CSS，不引入 highlight.js / Prism 等语法高亮库。
