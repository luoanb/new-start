# git_checkout

## 工具

将活动仓库切换到目标分支 / 提交（`target`）。若工作区有会被覆盖的未提交改动，属「危险写操作」（需开启危险写开关 + 用户确认）；工作区干净时直接执行。等同 `git checkout <target>`。

参数：

- `target`（必填）：要切换的分支或提交。

返回 JSON：干净场景 `{"target": "...", "ok": true}`；覆盖场景确认通过后 `{"cancelled": false, "result": {"target": "..."}}`，拒绝为 `{"cancelled": true}`。

## 对模型的期待

- 切换分支前先 `git_branch` 确认目标存在、`git_status` 确认工作区状态。
- 若工作区脏且开关未开，会直接报错——先帮用户提交 / 暂存改动，或提示开启「危险写操作」。

## 忌用

- 脏工作区下不要贸然 checkout（可能覆盖改动）。
- 不要用本工具创建新分支（本工具只切换已有分支 / 提交）。

## 注意

- 判定「脏」的依据：存在未暂存或未跟踪改动。
- 用户拒绝返回 `cancelled: true`，尊重决定。
