# git_commit

## 工具

用给定消息提交活动仓库的暂存区改动。需用户确认，确认弹窗会展示本次将提交的暂存文件清单。等同 `git commit -m`。

参数：

- `message`（必填）：提交消息。

返回 JSON：确认通过后 `{"cancelled": false, "result": {"message": "..."}}`；用户拒绝为 `{"cancelled": true}`。

## 对模型的期待

- 提交前先 `git_status` + `git_diff(cached=true)` 确认暂存内容符合提交意图。
- 消息应遵循仓库的提交风格，简洁说明「为什么」。
- 若暂存区为空，`git commit` 会失败——先 `git_add` 再提交。

## 忌用

- 暂存区包含无关文件时不要直接提交——先调整暂存内容。
- 存在冲突未解决时绝不提交。
- 不要用本工具绕过确认：用户拒绝后请尊重决定，必要时调整暂存内容再征询。

## 注意

- 消息经参数数组传入，不会被解析为 git 选项（安全）。
- 提交后工作区状态变化会广播给前端刷新。
