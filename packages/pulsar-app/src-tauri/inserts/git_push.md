# git_push

## 工具

将活动仓库的本地提交推送到远程（默认当前分支的上游）。需用户确认，确认弹窗展示当前分支与领先提交数。等同 `git push`。

参数（均为可选）：

- `remote`：远程名，默认 `origin`。
- `branch`：要推送的分支，默认当前分支。

返回 JSON：确认通过后 `{"cancelled": false, "result": {"remote": "...", "branch": "..."}}`；用户拒绝为 `{"cancelled": true}`。

## 对模型的期待

- 推送前先 `git_status` 确认分支与 `ahead` 领先数，向用户说明将推什么。
- 无上游分支时 git 会提示设置上游——按用户意图处理。

## 忌用

- 不要把本地未提交 / 未暂存内容当作「已推送」（push 只推已提交内容）。
- 不要使用 force push（本工具不提供，也绝不替代）。

## 注意

- 需要远端凭据时复用系统 git 凭据，不在工具层处理密码。
- 用户拒绝返回 `cancelled: true`，尊重决定。
