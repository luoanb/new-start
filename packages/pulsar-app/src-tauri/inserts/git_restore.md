# git_restore

## 工具

撤销活动仓库指定路径的未提交工作区改动（恢复到暂存区 / HEAD 状态），改动不可恢复。需用户确认。等同 `git restore -- <paths>`。

参数：

- `paths`（必填）：要丢弃改动的路径数组（相对仓库根）。

返回 JSON：确认通过后 `{"cancelled": false, "result": {"paths": [...]}}`；用户拒绝为 `{"cancelled": true}`。

## 对模型的期待

- 仅当用户明确要求放弃某文件改动时调用。
- 调用前先 `git_status` 确认这些路径确实有未提交改动，并在请求中说明将丢失的内容。

## 忌用

- 绝不未经确认门禁的语义偷偷撤销——本工具已强制走确认弹窗。
- 不包含已暂存的改动时需注意：`restore` 只影响工作区（未暂存部分）。
- 路径不得为绝对路径或含 `..`（会被拒绝）。

## 注意

- 丢弃的改动无法找回，务必让用户知情。
- 用户拒绝不视为错误：返回 `cancelled: true`，请尊重用户决定，不要重试。
